# Record: VER-066

| | |
|---|---|
| Requirements | VER-066 |
| Method | A |
| Check | Verify check `spec`: `cargo xtask assurance --strict` |

Verify check `spec` and the step `assurance` of `cargo xtask ci` (since 2026-10-25, M2 WP-8, branch `m2/assurance-check`; `xtask/src/assurance.rs`) run `cargo xtask assurance`, which reads the hazard analysis (`docs/verification/hazards.md` and the codec files of `docs/verification/hazards/`, VER-065) and the assurance case (`docs/verification/assurance-case.md`) and checks them as [assurance-evidence.md](../assurance-evidence.md) specifies:

- every reference, a code span `kind:target` of the 19 kinds of its §2.3, resolves: a file, a test (found in the tokens of the Rust file: a `#[test]` function, a function in `proptest!`, or a name passed to a local `macro_rules!` with `#[test]`), a Kani proof, a live or superseded vector case, a record, a gating or nightly-only check of `cargo xtask verify list`, a step of `cargo xtask ci`, a job of `nightly.yml`, a fuzz target, an open issue, and a hazard, claim, assumption, defeater, or proposal the files define; a `gh:` reference is counted and listed, not resolved (the check runs offline);
- evidence that runs only at night says so by its kind: `test:` rejects an ignored test, `nightly-test:` a test that is not ignored, `check:` a check that is not gating or is nightly only, `nightly-check:` a gating one, `vector:` a superseded case;
- every requirement ID of a `Requirements` cell or column is defined and not deleted;
- both documents follow their formats (hazard tables, coverage tables, proposals tables, claims with strategies or evidence tables, assumptions, defeaters), and every hazard that is not `todo` names a claim;
- an open defeater that names a resolved open issue is a problem.

With `--strict`, which joins `cargo xtask ci` and the check `spec` at the M2 exit, a hazard with the status `todo`, a coverage state `TODO`, and an evidence row `TODO` are problems too. The check writes `target/spec/assurance.json` and `target/spec/assurance.md`.

It does not check that a piece of evidence shows what the text says, that a record is true, that a nightly job passed, the state of an issue, or that the analysis is complete (assurance-evidence.md §6); those are the review of each pull request that changes the analysed files and of the milestone exit (VER-065).

The unit tests of `xtask/src/assurance.rs` cover each rule of the specification on fixture texts, and the repository itself.

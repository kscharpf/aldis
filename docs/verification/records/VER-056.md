# Record: VER-056

| | |
|---|---|
| Requirements | VER-056 |
| Method | I |
| Check | Review of each PR that touches `xtask/src/verify/` or `xtask/verify/` |

`cargo xtask verify` (`xtask/src/verify/`): the check table (`checks.rs`) has one check per former pull-request job of `ci.yml` and `cpp.yml`, under the same name, each portable except `test-macos` (macOS host) and the non-gating `cpp-leon3` (`x86_64` host); the other non-gating checks, `rust-sparc-leon3` and `kani` (the Kani proof harnesses, OI-42), are portable (tests in `checks.rs`); the image `xtask/verify/Containerfile` pins its base by digest and takes its tools from `rust-toolchain.toml`, `tooling-nightly`, and `cpp/toolchains.lock`; a dirty working tree is refused; each check declares its inputs (`checks.rs`: `RUN` for every check, `RUST`, `XTASK_TESTS`, `CPP`, and `FFI` for the check `header`, which reads `crates/**` and `include/**`, and `KANI` for the check `kani`, which reads the three crates with harnesses; `spec` reads every path; `DOCS`, `GITHUB`, the GitHub configuration that no other check reads, and `ROOT_CONFIG`, the root configuration that no other check reads (`.gitignore`: every check runs in a fresh checkout and none lists untracked files), are read by `spec` only), and a check is left out only when a published passing record of an earlier commit (the one covering the merge base with `origin/main`, or one of the branch's first-parent ancestors not on `main`, at most 20), followed to the record in which the check ran and passed, is of an ancestor whose paths that differ from the commit include none of the check's inputs and no unlisted path: `skipped` when its inputs are also unchanged against the base, else `reused`; every check runs on an unknown change, when no record exists for the base or the branch, or with `--all` (`scope.rs`: `sources`, `plan`; tests in `scope.rs` with throwaway git repositories, among them a branch that merges a `main` that changed only `cpp/` (Rust checks reused, C++ checks skipped) or a Rust input (Rust checks run), a source whose record fails the gate or that is not an ancestor (not used), records of formats 1, 2, and 3 followed to their origin, and a change to the workflows or the pull-request template, which runs only `spec`; and in `checks.rs`, including one that every file that Rust code includes is a Rust input). The checks run in `checks::run_order`: the gating checks first, then the non-gating ones, each by its declared typical duration (`Check::secs`, the median of the GitHub-hosted records), so that a run with `--fail-fast` (the default with `--publish`) stops at the first gating check that fails and records each check it did not reach as `not-run` with the reason; a non-gating check never stops a run (`mod.rs`: `run_in_order`; tests in `mod.rs` and `checks.rs`). A nightly-only check (`Check::nightly`, only `kani`) runs only with `--all`; `scope::plan` decides it as not run with the reason "nightly only (VER-059)", whatever its inputs and records, so it is never skipped, reused, or a source, and never makes a run start a container (tests in `checks.rs`, `scope.rs`, and `mod.rs`). A run whose input rule runs no gating container check starts no container (`mod.rs`: `no_container`, `without_container`): the non-gating checks it would run are `not-run`, and the record passes the gate (tests in `mod.rs`). Reviewed in each PR that touches `xtask/src/verify/` or `xtask/verify/`

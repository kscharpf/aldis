# Record: VER-012

| | |
|---|---|
| Requirements | VER-012 |
| Method | I |
| Check | Inspection of the step function of each engine and of every `next_deadline`, with the loop list of `cargo xtask loops list`, 2026-11-05 |

Every loop of the library is bounded (GEN-022, [GEN-022](GEN-022.md)), and no step function recurses, so the worst case of a step is the sum of its loops, each over a slice whose length is an input length or a capacity. The table gives that sum for each engine, from the loops of the file named. Capacities are the const generics of the engine's type (`D` octets of a data field, `Q` octets of a queue, `V` virtual channels, `F` octets of a frame, `M` MAPs, `S` octets of an SDU, `U` octets of a data unit, `N` actions, [04](../../04-engines.md) §4); `n` is the octets of the input. The number of actions and the output area of each input are in [04](../../04-engines.md) §4 and are not repeated.

|---|---|---|---|
| FARM-1 (`file:crates/aldis-cop1/src/farm1.rs`) | every input | O(`n`) | One table cell: at most the actions of a cell (a constant), and a copy of the FDU to the output area (`run`). `Reconfigure` and `next_deadline` do not exist: FARM-1 has no timer. |
| FOP-1 (`file:crates/aldis-cop1/src/fop1.rs`) | `decide` | O(`Q` + `F`) | The cell's actions, each of which walks the Sent_Queue of at most `Q` entries (`remove_acked`, `purge_sent`, `look_for_fdu`, `push_sent`), and encodes at most one frame of at most `F` octets into the output area. |

What the inspection did not do: it does not measure cycles, and the bounds are in operations of the loops, not in time on a target. The stack bound of each entry point is [VER-011](VER-011.md). A change that adds a loop to a step function changes this table in the same pull request: `cargo xtask loops list` shows the loops of each file.

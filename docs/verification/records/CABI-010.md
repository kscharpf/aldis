Review of `crates/aldis-ffi/src/` and the generated header in M2 WP-0c (2026-10-21): only fixed-width integers, `size_t`, `bool`, and `#[repr(C)]` structs of them cross the ABI, enumerations are integer fields or arguments with `ALDIS_*` constants, and buffers are `(const uint8_t *, size_t)` or `(uint8_t *, size_t, size_t *)`; the handles are opaque struct pointers. Reviewed again for `src/tm.rs` (M2 WP-2 module 7, branch `m2/tm-c-abi`, 2026-10-23): the TM configuration, fields, header, layout, and view structs hold only `uint8_t`, `uint16_t`, `uint32_t`, `size_t`, and `bool` (in output structs only), the data field content and the First Header Pointer class are `uint8_t` members with `ALDIS_TM_*` constants, and every field buffer is a `(const uint8_t *, size_t)` pair. Since the review of #94 (maintainer decision 2026-10-24, c-abi.md §11) the five frame-content buffers of `aldis_tm_encode` are such pairs as members of the input struct `aldis_tm_content_t`, the one struct of the ABI that holds pointers. Reviewed again for `src/uslp.rs` (M2 WP-5 module 9, branch `m2/uslp-c-abi`, 2026-10-24): the USLP configuration, channel, fields, TFDF, layout, view, and delimited-item structs hold only `uint8_t`, `uint16_t`, `uint32_t`, `uint64_t`, `size_t`, and `bool` (in output structs only), the frame type, OCF use, security scope, source-or-destination, frame kind, construction rule, and item kind are `uint8_t` members with `ALDIS_USLP_*` constants, the UPID is a `uint8_t` of 0 to `ALDIS_USLP_UPID_MAX` with constants for the values the SANA snapshot assigns, the validation reason a `uint32_t` out-parameter with `ALDIS_USLP_REASON_*` constants, and the Insert Zone, TFDZ, and OCF of a frame `(const uint8_t *, size_t)` pairs as members of the input struct `aldis_uslp_content_t` (c-abi.md §11). Reviewed again for `src/aos.rs` (M2 WP-4 module 8, branch `m2/aos-c-abi`, 2026-10-24): the AOS configuration, fields, header, data unit, layout, and view structs hold only `uint8_t`, `uint16_t`, `uint32_t`, `size_t`, `bool` (in output structs only), and the fixed `uint8_t[8]` of the corrected header octets; the edition, the Data Field Content, and the pointer class are `uint8_t` members or arguments with `ALDIS_AOS_*` constants; the five frame-content buffers of `aldis_aos_encode` are `(const uint8_t *, size_t)` pairs in the input struct `aldis_aos_content_t`, as c-abi.md §11 allows, and no other AOS struct holds a pointer. Reviewed in each PR that changes `aldis-ffi`

The TC configuration, fields, header, layout, view, delimiter item, Control Command, and CLCW structs hold only `uint8_t`, `uint16_t`, `uint32_t`, `size_t`, and `bool` (in output structs only); the frame type, Sequence Flags, Control Command, and delimiter item kind are `uint8_t` members with `ALDIS_TC_*` constants, and the validation reason a `uint32_t` with `ALDIS_TC_REASON_*`. `aldis_clcw_t` is an input of `aldis_clcw_encode` and an output of `aldis_clcw_decode`, so its flags are `uint8_t` 0 or 1, as an input struct's are.

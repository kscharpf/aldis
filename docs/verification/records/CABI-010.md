Review of `crates/aldis-ffi/src/` and the generated header in M2 WP-0c (2026-10-21): only fixed-width integers, `size_t`, `bool`, and `#[repr(C)]` structs of them cross the ABI, enumerations are integer fields or arguments with `ALDIS_*` constants, and buffers are `(const uint8_t *, size_t)` or `(uint8_t *, size_t, size_t *)`; the handles are opaque struct pointers. Reviewed again for `src/tm.rs` (M2 WP-2 module 7, branch `m2/tm-c-abi`, 2026-10-23): the TM configuration, fields, header, layout, and view structs hold only `uint8_t`, `uint16_t`, `uint32_t`, `size_t`, and `bool` (in output structs only), the data field content and the First Header Pointer class are `uint8_t` members with `ALDIS_TM_*` constants, and every field buffer is a `(const uint8_t *, size_t)` pair. Since the review of #94 (maintainer decision 2026-10-24, c-abi.md §11) the five frame-content buffers of `aldis_tm_encode` are such pairs as members of the input struct `aldis_tm_content_t`, the one struct of the ABI that holds pointers. Reviewed again for `src/aos.rs` (M2 WP-4 module 8, branch `m2/aos-c-abi`, 2026-10-24): the AOS configuration, fields, header, data unit, layout, and view structs hold only `uint8_t`, `uint16_t`, `uint32_t`, `size_t`, `bool` (in output structs only), and the fixed `uint8_t[8]` of the corrected header octets; the edition, the Data Field Content, and the pointer class are `uint8_t` members or arguments with `ALDIS_AOS_*` constants; the five frame-content buffers of `aldis_aos_encode` are `(const uint8_t *, size_t)` pairs in the input struct `aldis_aos_content_t`, as c-abi.md §11 allows, and no other AOS struct holds a pointer.

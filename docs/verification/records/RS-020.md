# Record: RS-020

| | |
|---|---|
| Requirements | RS-020 |
| Method | A, I |
| Check | Review of each PR that adds or changes a public type; `cargo xtask rs020`; `cargo xtask restricted` |

Reviewed in each PR that adds or changes a public type. Audit of `aldis-core`, `aldis-epp`, and `aldis-time` on 2026-10-19: the CCS and CDS value types were brought into line in PR #21, and the remaining violations and gaps listed in [issue #22](https://github.com/kscharpf/aldis/issues/22) (`FrameCtx`, `FrameLayout`, `SecuredFields`, `EncapsulationFields`, the EPP sender-side check, `TimeCodeId`, `TimeCode::Unknown`, `Cuc::from_seconds_nanos`, the `Anomaly` trait) in the PR closing it.

Since 2026-10-24 (M2 WP-7, branch `m2/rs020-check`), `cargo xtask rs020` (`xtask/src/rs020.rs`; part of `cargo xtask ci` and the verify check `spec`) also checks one pattern mechanically: in the public API of the codec crates (`aldis-core`, `-time`, `-spp`, `-epp`, `-tm`, `-tc`, `-aos`, `-uslp`), every enum variant whose payload includes a bare integer and every `pub` field of a public type that is one is a problem unless [`xtask/rs020-exemptions.toml`](../../../xtask/rs020-exemptions.toml) exempts it with a reason; an exemption without a reason, or that matches no item, is a problem too. Its first run found 21 bare integers: four were gaps and became types (`aldis_aos::PacketOffset`, `aldis_tm::PacketOffset`, and `aldis_uslp::TfdzOffset` for both pointers), and 17 are exempted. The C ABI still takes the TM packet offset as a `uint16_t`; an offset above `0x7FD` fails with the error and detail the writer gave before, at the same point (`crates/aldis-ffi/tests/tm.rs`, `packet_offsets_above_0x7fd_fail_as_the_writer_checks_them`, which passes on the code before the change too). The check reads the source textually, so a type that a macro invocation builds is checked only where the `macro_rules!` body defines it; review covers the rest of RS-020.

Since 2026-10-24 (M2 WP-7, branch `m2/wp7-tests`), `cargo xtask restricted` (`xtask/src/restricted.rs`; part of `cargo xtask ci` and the verify check `spec`) checks that every *restricted type* of the same crates has a test: a public struct or enum with a checked constructor, an inherent `pub fn` that takes its arguments by value and returns `Option<Self>` or `Result<Self…>`, or a `TryFrom` impl (a type a `macro_rules!` body defines counts once per invocation). A test of the crate (`crates/<crate>/tests/restricted.rs`) names each one in a `// restricted: <Type>` marker; a type without a marker, or a marker that names no restricted type, is a problem. Each such test shows that the constructor accepts exactly the range the cited clause or requirement gives (exhaustively over every `u8`, `u16`, and `bool` input), rejects every other value with the documented error, and that every accepted value survives its wire field. `cargo xtask restricted list` prints the types it finds. A constructor that takes a reference (a frame writer, a channel table built from a slice, `Agency::new` over the T-field) or decodes (`decode…`, `parse…`) does not make a type restricted in this sense; the codecs' property tests cover those.

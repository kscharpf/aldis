The computations of `cargo xtask metrics` (`xtask/src/metrics/`) are unit-tested on fixture JSON and a throwaway git repository, without the network (`// req: VER-063`, run by the verify checks `test`, `test-macos`, and `big-endian`). What the tests cannot show is inspected: that the command only reads GitHub (every `gh api` call is a `GET`) and changes nothing in the local repository but fetched objects, the notes ref `refs/notes/verify-origin` that `verify check` also fetches, and the tree objects that `git merge-tree --write-tree` writes (no branch, index, or working tree); that `cargo xtask ci` does not run it (`xtask/src/main.rs`); and that the `metrics` job of `.github/workflows/nightly.yml` has `continue-on-error: true`, is not in the `needs` of the `issue` job, holds `contents: read`, `issues: write`, and read access to pull requests, statuses, and workflow runs only, and edits the body of the one issue labelled `metrics` rather than commenting. Inspected 2026-10-21, when the command and the job were added; the first report, for 2026-10-16 to 2026-10-21, was made locally with `cargo xtask metrics --since 2026-10-16` and checked against `gh pr view` for #70 and #74.

The stages and the process-created waits (`chore/metrics-stages`, 2026-10-24; VER-063 states them since the maintainer accepted the wording on 2026-10-24, [06 §9](../../06-verification.md#9-process-metrics)) add three reads and one local write, for the review of that pull request to inspect: the repository's issue comments (`gh api …/issues/comments`, a `GET`); `git log -S` over `docs/process/decisions.md`, which reads history only; and `gh run download` of the artefact `verify-<sha>` of each failed `verify.yml` run, which reads it from GitHub and writes it under `target/metrics-runs/<run>/`, outside the tracked files and outside `target/metrics/`, the directory the nightly job keeps as its artefact. The live report of 2026-09-24 to 2026-10-24 was checked by hand against #94 (its decision comment and review), #98 (the failed run `3ce83c27` and its first gating failure `header`), and the dependency rule against the commits of #100, which merges #98's head `8e1e6b4` (#100 is still open, so the report does not list it).

The process overhead (`chore/process-followups`, 2026-10-24, `xtask/src/metrics/overhead.rs`; VER-063 states it since the maintainer's decision of that day) adds two local reads, for the review of that pull request to inspect: `git diff-tree --name-only -r` of each commit of a pull request other than a merge, and `git show <commit>:<path>` of a milestone plan before and after such a commit, both of which read objects only. Its classification of paths, its shares, the bookkeeping-only commits (a plan counts only when every line that changed is a row of its work-package status table), and the two thresholds of the "Recommendations input" (process-only pull requests at 33 % or more of the period's verification minutes; two or more bookkeeping-only commits in one pull request, where one, the commit of the decision-log lines, is expected) are unit-tested on recorded fixtures and a throwaway git repository (`overhead.rs`, `report.rs`, `mod.rs`).

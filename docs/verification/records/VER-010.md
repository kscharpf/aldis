# Record: VER-010, GEN-020, GEN-021

| | |
|---|---|
| Requirements | VER-010, GEN-020, GEN-021 |
| Method | A |
| Check | Verify checks `exerciser-<target>` |

Verify checks `exerciser-<target>`, and the nightly CI job `exerciser`: `exerciser/` calls every public `aldis-core` API with the core vectors (`exerciser/src/exercise.rs`, and `ocf.rs` for the OCF, M2 WP-1), every public `aldis-time`, `aldis-spp` (with `time`), and `aldis-epp` API (`exerciser/src/time.rs`, `spp.rs`, `epp.rs`), and the implemented `aldis-aos` API, the FHEC (`exerciser/src/aos.rs`, M2 D16). It also runs every live case of `test-vectors/{time,spp,epp,aos}/`, which `exerciser/build.rs` embeds, and compares every output exactly, as the host suites do (`exerciser/src/vectors.rs`, TV-012). Inputs pass through `black_box`. The calls were checked complete on 2026-10-19 (M1 WP-5) against the symbols an unoptimized exerciser build references. The release build (LTO, `panic = "abort"`) links with a panic handler that calls the undefined `aldis_panic_is_unreachable` on thumbv7em, armv7r, and riscv32imac. The `inject-panic` canary must fail to link with that symbol, so the check cannot pass vacuously. The exerciser then runs under QEMU 8.2 on every target and exits through semihosting with failure if any case fails or any exception or trap occurs (M1 D6): Cortex-M4 on `mps2-an386`, Cortex-R5F on the `none` machine (`mps3-an536`, Cortex-R52, needs QEMU ≥ 9.0), and RV32 on `virt`. `epp-idle-009`, a total length of 2^32, does not fit a 32-bit `usize`; the run reports it as not representable. `cargo xtask consistency` fails when a gated crate is not an exerciser dependency, has no vector group in `exerciser/build.rs`, or a vector file of an exercised crate is not embedded.

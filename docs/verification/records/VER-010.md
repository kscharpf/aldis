It also runs every live case of `test-vectors/{time,spp,epp,aos,tm,tc,uslp}/`, which `file:exerciser/build.rs` embeds, and compares every output exactly, as the host suites do (`file:exerciser/src/vectors.rs`, TV-012). Inputs pass through `black_box`. The calls were checked complete on 2026-10-19 (M1 WP-5) against the symbols an unoptimized exerciser build references. Since M2 WP-0c it also calls every function `aldis-ffi` exports (`file:exerciser/src/ffi.rs`, M2 plan D16; the aldis_tm_* functions since M2 WP-2 module 7: 1379 cases, 0 failed, 1 not representable on thumbv7em under QEMU, 2026-10-23; the aldis_uslp_* functions since M2 WP-5 module 9, with the since-deleted writer resume and the Galois OID encoder in the `aldis-uslp` group: 2161 cases, 0 failed, 1 not representable on thumbv7em under QEMU, 2026-10-24), with the panic handler of `aldis-ffi`'s feature `panic-unreachable`, so the link check covers the C ABI. The release build (LTO, `panic = "abort"`) links with a panic handler that calls the undefined panic-unreachable symbol on thumbv7em, armv7r, and riscv32imac. The `inject-panic` canary must fail to link with that symbol, so the check cannot pass vacuously. The exerciser then runs under QEMU 8.2 on every target and exits through semihosting with failure if any case fails or any exception or trap occurs (M1 D6): Cortex-M4 on `mps2-an386`, Cortex-R5F on the `none` machine (`mps3-an536`, Cortex-R52, needs QEMU ≥ 9.0), and RV32 on `virt`. `epp-idle-009`, a total length of 2^32, does not fit a 32-bit `usize`; the run reports it as not representable.

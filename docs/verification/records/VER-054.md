# Record: VER-054

| | |
|---|---|
| Requirements | VER-054 |
| Method | I |
| Check | Review of the shared strategies in `aldis_testkit::strategies` |

The property-test input strategies are defined once, in the tooling crate `aldis-testkit` (RS-017), as `aldis_testkit::strategies` behind the features `strategies`, `strategies-time`, `strategies-spp`, and `strategies-epp` (`crates/aldis-testkit/src/strategies/`; M2 plan D6): `common` (`aldis-core` identifiers with their out-of-range raw values, decode mode, counters, bit fields, frame layouts, queue operations), `time`, `spp`, and `epp` (formats, configurations, headers, and whole data units built through the crates' checked constructors and encoders, and decoder input next to each boundary: one octet too short, a length field off by one, a version or reserved value changed). Every property test of `aldis-core`, `aldis-time`, `aldis-spp`, and `aldis-epp` is an integration test, `crates/<crate>/tests/properties.rs`, that draws its inputs from them, and none of these crates depends on `proptest` directly; each strategy's own tests check that its values are what it documents (valid codes decode strictly, codes with undefined P-field octets only leniently, a length off by one is noticed). Reviewed in each PR that adds a property test or a strategy; the differential tests of `difftest/` (VER-053, track C, C1) are to use the same module

# Record: VER-054

| Check | Review of the shared strategies in `aldis_testkit::strategies` |

The property-test input strategies are defined once, in the tooling crate `aldis-testkit` (RS-017), as `aldis_testkit::strategies` behind the features `strategies`, `strategies-time`, `strategies-spp`, `strategies-epp`, `strategies-tm`, `strategies-tc`, `strategies-aos`, and `strategies-uslp` (`crates/aldis-testkit/src/strategies/`; M2 plan D6): `common` (`aldis-core` identifiers with their out-of-range raw values, decode mode, counters, OCF octets, security layouts and secured ranges, bit fields, frame layouts, queue operations), `time`, `spp`, and `epp` (formats, configurations, headers, and whole data units built through the crates' checked constructors and encoders, with the out-of-range values of their restricted types), and `tm`, `tc`, `aos`, and `uslp` (header fields, packet offsets and counts, channel configurations, and whole frames built by the crates' encoders), and decoder input next to each boundary: one octet too short, a length field off by one, a version or reserved value changed. Every property test of the codec crates is an integration test, `crates/<crate>/tests/properties.rs`, or, for the tests of the restricted types (M2 plan WP-7, `cargo xtask restricted`), `crates/<crate>/tests/restricted.rs`, that draws its inputs from them, and none of these crates depends on `proptest` directly; each strategy's own tests check that its values are what it documents (valid codes decode strictly, codes with undefined P-field octets only leniently, a length off by one is noticed, an out-of-range value is out of range). The bit-flip suites (`crates/<crate>/tests/bit_flips.rs`) enumerate their errors deterministically rather than draw them, with `aldis_testkit::bitflip`. Reviewed in each PR that adds a property test or a strategy, last on 2026-10-24 (`m2/wp7-tests`); the differential tests of `difftest/` (VER-053) were deferred with Track C retirement (chore/retire-track-c).

# Record: API-050

| | |
|---|---|
| Requirements | API-050 |
| Method | I |
| Check | Inspection of `aldis-cop1` and of the `aldis-ffi` engine functions for caller code, 2026-10-31 (M3 exit) |

The engines take their inputs as data and return their actions as data: `Fop1::decide`, `Fop1::commit`, `Farm1::step` in `file:crates/aldis-cop1/src/fop1.rs` and `file:crates/aldis-cop1/src/farm1.rs`, and the `aldis_fop1_*` and `aldis_farm1_*` calls in `file:crates/aldis-ffi/src/fop1.rs` and `file:crates/aldis-ffi/src/farm1.rs`.

What the inspection looked for, and found:

- `aldis-cop1` declares no trait, no `dyn`, no `Box`, no function-pointer type, and no generic parameter bounded by `Fn`, `FnMut`, or `FnOnce` in a public or private signature. Its only closure parameter is the private `remove_sent` helper of `file:crates/aldis-cop1/src/fop1.rs`, which receives a closure written in the same file.
- SDLS is not an engine input as code: `SecurityHook` is not referenced in `aldis-cop1` (OI-56, H5; API-074).
- `file:include/aldis/aldis.h` has no function-pointer typedef or parameter, and no `aldis_fop1_*` or `aldis_farm1_*` call takes a callback (CABI-040).
- The only closures of the FFI engine path are the `FnOnce` arguments of the private `Handle::read`, `Handle::update`, and `init_with` in `file:crates/aldis-ffi/src/handle.rs`, which run library code lent the state for the duration of one call.

Redo the inspection in every PR that adds a public item to `aldis-cop1` or a function to `crates/aldis-ffi/src/fop1.rs` or `crates/aldis-ffi/src/farm1.rs`.

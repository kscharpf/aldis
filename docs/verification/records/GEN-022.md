# Record: GEN-022, GEN-023

| | |
|---|---|
| Requirements | GEN-022, GEN-023 |
| Method | A |
| Check | Verify check `spec` (`cargo xtask loops`, the loop-bound annotations); verify check `stack` (VER-011); Kani proof harnesses; `#![no_std]` architecture verification |

GEN-022 (bounded loops, no recursion) and GEN-023 (bounded execution time, non-blocking) are verified by analysis (**A**):

1. **Loop bounds (GEN-022), checked mechanically by `cargo xtask loops`** (part of `cargo xtask ci` and of the verify check `spec`; `file:xtask/src/loops.rs`). The scanner finds every loop in the library code of every crate: `for`, `while`, `while let`, `loop`, the iterator methods that consume an iterator (`sum`, `any`, `collect`, …), and the slice methods that run over a slice (`fill`, `copy_from_slice`, …). It sorts them in two:
   - **Bounded by construction.** A `for` loop or consumer whose source is a slice, an array, a fixed container, or a range with an end, and the slice methods. The bound is the length of what they iterate, which the type gives. These need nothing.
   - **Bounded by annotation.** Every `while`, `while let`, and `loop`, and every iteration whose source holds an open range (`n..`) or `repeat`, `repeat_with`, `cycle`, `from_fn`, or `successors`. Each carries a `// bound: <reason>` comment directly above it that states the bound and why the loop reaches it (an input length, a capacity `N`, a constant, or a variant that falls on each pass). The check fails on such a loop without the comment, on a comment without a reason, and on a comment that is not directly above a loop. `cargo xtask loops list` prints every loop and which kind it is.

   The check proves that a stated bound exists for each loop that is not bounded by its type; it does not prove the stated reason true. The reasons are read by reviewers of the pull request that adds the loop, and the loops with complex bounds (CRC table calculation and bitwise updates, the `ErrorKind` catalogue lookup, bit-field manipulation) are also proven by Kani harnesses (`file:crates/aldis-core/src/proofs.rs`, [formal-proofs.md](../formal-proofs.md) §2; nightly). The scanner is textual and reads library code only (not `cfg(test)` or `cfg(kani)` code); a loop built by a macro of another crate, or an iterator whose `next` the library itself defines, is not seen.
2. **Recursion (GEN-022):** The verify check `stack` (record [VER-011](VER-011.md), `file:xtask/src/stack.rs`) builds the call graphs of the C ABI static library and of the exerciser directly from their object code and LLVM IR for three bare-metal architectures (thumbv7em, armv7r, riscv32imac) and fails on any call cycle. This guarantees that no recursion reaches any library entry point. The per-crate call graphs of the earlier inspection records are not kept.
3. **Execution time and non-blocking (GEN-023):** The library crates are `#![no_std]`, heap-free (GEN-010, GEN-011), and deterministic with sans-I/O engines (GEN-030). There are no operating system syscalls, no blocking I/O, no sleep calls, no threads, and no locks. With every loop bounded (1) and no recursion (2), every operation finishes in O(input length + capacities), the product of the loop bounds, each an input length, a capacity, or a constant. This follows from items 1 and 2 and from the absence of anything to wait on; no inspection of further exceptions is needed. The one loop that never ends, annotated as such, is the panic handler of a firmware build in `aldis-ffi`, which no API call reaches (GEN-020, GEN-021).

**Historical record:** Through releases `v0.2.0-m1` and `v0.3.0-m2`, GEN-022/GEN-023 were tracked via per-crate Markdown inspection records (`docs/verification/inspections/gen-022-023-<crate>.md`) under requirement VER-061. Those inspections were reviewed and approved by the maintainer across milestones M1 and M2 (see git history). On 2026-10-28, VER-061 and the per-PR Markdown inspection tables were retired in favor of automated call-graph analysis (`check:stack`), formal verification, and architectural constraints. On 2026-10-29, the loop-bound half was made mechanical: `cargo xtask loops` returned to the gate and the bounds moved from tables into `// bound:` comments next to the loops.

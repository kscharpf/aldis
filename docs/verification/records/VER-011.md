Verify check `stack` (since 2026-10-24, M2 WP-7, branch `m2/wp7-checks`; `xtask/src/stack.rs`): `cargo xtask stack` builds the `aldis-ffi` static library as it ships (`--no-default-features --features panic-handler --release`) for thumbv7em, armv7r, and riscv32imac on the tooling nightly, with `core` and `compiler_builtins` built from source (`-Z build-std=core`) and `-Z emit-stack-sizes --emit=llvm-ir,link`. The release profile's LTO does not apply to `aldis-ffi`, whose crate types include `rlib`, so the archive holds one object per crate. From the objects it takes each function's frame (`.stack_sizes`) and the call graph (the relocations of each function: calls, tail calls, and addresses taken), and checks the graph complete against the LLVM IR of the same compilation: a reachable function with an indirect call (`dyn`, a function pointer), inline assembly, a dynamic stack allocation, no frame, or no IR, a call that no object defines, and a cycle (GEN-022) each fail, unless `xtask/stack-budgets.toml` exempts the function with a stated bound. The entry points are the `aldis_*` functions of the C ABI and every global function of a Rust library crate's object (each public non-generic function, and the functions that generic and inline public code calls); a generic function is measured where the C ABI instantiates it, with the capacities of `crates/aldis-ffi/capacities.toml`. The worst case of an entry point, its frame plus the deepest chain of callee frames, must stay within its target's budget for its kind (`rust`, `c-abi`) in `xtask/stack-budgets.toml`; the budgets are the maintainer's. The bound leaves out interrupts and the caller's frames. The check's inputs are `RUN` (which holds `xtask/`, the budgets file, and `tooling-nightly`) and `crates/**`; it takes about 25 s per target on a warm macOS host.

The published table is the report of the same run, `target/spec/stack-<target>.md`: every entry point with its worst case and deepest path, the exemptions applied, and the frame of every function reached. The nightly job `stack-sizes` runs `cargo xtask stack <target>` for each target and keeps the report as the artefact `stack-sizes-<target>`, also when a budget fails; the release takes it from the nightly run of the release commit.

Exemptions (2026-10-24): `<aldis_core::error::Error as core::fmt::Display>::fmt`, whose `core::fmt` callees (`core::fmt::write`, `Formatter::pad`, `Formatter::pad_integral`) call the caller's `core::fmt::Write` through a `dyn` reference (0 bytes: the writer is the caller's code); `__aeabi_uldivmod` on the two ARM targets, assembly in `compiler_builtins` with a 24-byte frame read from its disassembly.

Measured 2026-10-24 (`nightly-2026-10-15`, `m2/wp7-checks`), 235 entry points per target (122 Rust, 113 C ABI), about 375 functions reached, no indirect call or recursion outside the exemptions:

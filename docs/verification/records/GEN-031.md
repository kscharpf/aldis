# Record: GEN-031, GEN-032

| | |
|---|---|
| Requirements | GEN-031, GEN-032 |
| Method | A, I |
| Check | Verify checks `no-std-<target>` (with `cargo xtask ffi-imports`) and `layers`, with an inspection of the library sources |

Layers 0 to 2 (`aldis-core`, `aldis-time`, `aldis-spp`, `aldis-epp`, `aldis-tm`, `aldis-tc`, `aldis-aos`, `aldis-uslp`) can reach no clock, random source, environment variable, global mutable state, I/O, or log. What shows it:

1. **No platform API.** Each crate is `#![no_std]` (the crate root of each crate). The `alloc` and `std` features are additive and off in the flight build (GEN-005, GEN-006; check `features`), and the checks `no-std-<target>` build `aldis` with `--no-default-features --features full` for thumbv7em, armv7r, and riscv32imac, targets that have no `std`. So no flight build can name std::time, std::env, std::fs, std::io, std::net, std::process, or `println!`. With the `std` feature the crates only declare `extern crate std`, and the only uses of std:: in `src/` are in `#[cfg(test)]` modules (inspection, 2026-10-25: a text search for `std` and `alloc` paths over the eight crates).
2. **No dependency.** Layers 0 to 2 have no third-party runtime dependency (GEN-001; check `layers`, `records/GEN-001.md`), so no crate brings a clock, a random source, or a logger.
3. **No `unsafe`.** `#![forbid(unsafe_code)]` (GEN-070, `records/GEN-070.md`), so no code reads a hardware register, a foreign symbol, or a `static mut`.
4. **No global mutable state.** Inspection of the library sources of the eight crates and of `aldis-ffi` on 2026-10-25, searching for `static mut`, `static` items, `Cell`, `RefCell`, atomics, `Mutex`, `thread_local`, `OnceLock`, and `lazy_static`: the only `static` item is the CRC-16 lookup table, an immutable `[u16; 256]` computed in a `const` block (`file:crates/aldis-core/src/crc.rs`, feature `crc-table`). No interior-mutable type is used. The panic handler of `aldis-ffi` (`file:crates/aldis-ffi/src/lib.rs`) is the platform's hook, not state. State between calls is a value the caller owns.
5. **The shipped library imports nothing from a platform.** `cargo xtask ffi-imports <target>` (CABI-004, `records/CABI-004.md`) lists the symbols the static library leaves undefined and fails on any beyond `memcpy`, `memmove`, `memset`, `memcmp`, and `bcmp`. The library can therefore call no clock, random, file, or console function of the platform. The exerciser link (VER-010) builds the same code with no `std`.

What this does not show: `aldis-ffi` is Layer 3 and outside GEN-031 and GEN-032, and the `Instant` values of the engines (M3) are inputs, not clock reads. Review of any new `static`, interior-mutable type, or use std:: in library code is part of the review checklist of a pull request that adds one; no check searches for them, so a later change relies on that review and on items 1 to 3, which fail the build for a platform API.

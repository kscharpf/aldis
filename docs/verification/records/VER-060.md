`.github/workflows/verify.yml`: `workflow_dispatch` is its only trigger and branches its only refs; it runs `cargo xtask verify --publish` on `ubuntu-24.04` with `contents: write` (the notes ref) and `statuses: write`, and uploads `target/verify/*/`; `file:xtask/src/verify/mod.rs` writes the record's `source` from the GitHub Actions environment, and `file:xtask/src/verify/publish.rs` sets the status's `target_url` to the run. The image: `verify.yml` sets `ALDIS_VERIFY_PULL=ghcr.io/kscharpf/aldis-verify` and has `packages: write`; `file:xtask/src/verify/image.rs` pulls `<16 hex digits of the input hash>-<arch>` only when the image's labels `dev.aldis.verify.inputs` (the full hash) and `org.opencontainers.image.revision` match the hash it computes for the commit and the hash it recomputes from that revision's files, and its architecture is the host's, and else builds; `verify.yml` runs `cargo xtask verify --publish --push-image ghcr.io/kscharpf/aldis-verify` in this repository (plain `--publish` elsewhere), which gets the image only when a gating check needs the container (a run that needs none neither pulls nor builds one), and then pushes it if it was built, before any check runs; `verify image --push` (nightly) and `--push-image` push a built image only under GitHub Actions, after the workflow's `docker login` with `GITHUB_TOKEN`, guarded by `github.repository == 'kscharpf/aldis'`; the record's `image.source` is `built` or `pulled` with the reference, digest, and revision (test in `file:xtask/src/verify/image.rs` for the tag and the recomputed hash).

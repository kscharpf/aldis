`.github/workflows/verify.yml`: `workflow_dispatch` is its only trigger and branches its only refs; it runs three stages on `ubuntu-24.04`: `prepare` (`contents: read`, `packages: write`) decides from `cargo xtask verify list` whether the run starts a container and then makes sure the registry has the image; four `part` jobs (`contents: read`, `packages: read`; `fail-fast`) run `cargo xtask verify part <group>` and upload their `target/verify/*/` also when they fail; `assemble` (`contents: write` for the notes ref, `statuses: write`) downloads the part records outside `target/verify/<commit>` and runs `cargo xtask verify assemble --publish`, then uploads the record (VER-067); `file:xtask/src/verify/mod.rs` writes the record's `source` from the GitHub Actions environment, and `file:xtask/src/verify/publish.rs` sets the status's `target_url` to the run. The image: `verify.yml` sets `ALDIS_VERIFY_PULL=ghcr.io/kscharpf/aldis-verify`; `prepare` has `packages: write` and the parts `packages: read`; `file:xtask/src/verify/image.rs` pulls `<16 hex digits of the input hash>-<arch>` only when the image's labels `dev.aldis.verify.inputs` (the full hash) and `org.opencontainers.image.revision` match the hash it computes for the commit and the hash it recomputes from that revision's files, and its architecture is the host's, and else builds; `prepare` runs `cargo xtask verify image --push ghcr.io/kscharpf/aldis-verify` in this repository, only when `verify list` says the run starts a container (a run that needs none neither pulls nor builds one), which pulls the image or builds and pushes it before any part starts; in another repository the parts build it; `verify image --push` (nightly) and `--push-image` push a built image only under GitHub Actions, after the workflow's `docker login` with `GITHUB_TOKEN`, guarded by `github.repository == 'kscharpf/aldis'`; the record's `image.source` is `built` or `pulled` with the reference, digest, and revision (test in `file:xtask/src/verify/image.rs` for the tag and the recomputed hash).

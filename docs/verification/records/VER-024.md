# Record: VER-024

| | |
|---|---|
| Requirements | VER-024 |
| Method | A |
| Check | Verify check `coverage`: `cargo xtask coverage` |

Verify check `coverage`: `cargo xtask coverage` runs `cargo llvm-cov --branch` (0.9.1) on the tooling nightly and requires 100 % of regions, functions, lines, and branches in `aldis-core`, `aldis-time`, `aldis-epp`, `aldis-spp`, `aldis-aos`, and `aldis-tc` (with `--all-features`), less the waivers in `coverage-waivers.toml` (none; an oversized waiver also fails). Test modules are excluded with `coverage(off)`. `aldis-ffi` is measured and reported, not gated (`REPORTED` in `xtask/src/coverage.rs`, M2 plan D16). `llvm-cov` counts each function by its best-covered instantiation, not by the union of them, and a crate's unit tests and its integration tests run two different copies of the crate, so each function must be covered completely by one of the two (found when the property tests became integration tests, M2 WP-0b); the crate's tests also link no other codec crate, whose expansions of `aldis-core` macros would count against `aldis-core` (the per-crate `strategies-*` features of `aldis-testkit`). `cargo xtask consistency` fails when a Layer 0–2 crate that declares a function is not in `GATED`, or a gated crate is a skeleton.

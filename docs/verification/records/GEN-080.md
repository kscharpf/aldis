GEN-080 is a policy of the release process. What carries it, and what each part of it needs from a person:

- **Semantic Versioning.** The workspace version is `version` in `file:Cargo.toml`, and the C ABI reports its own in `ALDIS_ABI_VERSION_MAJOR/MINOR/PATCH` (`file:crates/aldis-ffi/src/lib.rs`, CABI-060). While the major version is 0, an incompatible change of the Rust API or the C ABI raises the minor version, as Cargo reads 0.x versions (CABI-033, withdrawn; CABI-060). D6 sets the major version to 1 with the v1.0 release; from then on CABI-060 and GEN-080 apply in full, and a breaking change raises the major version. The maintainer cuts every release and sets the version (AGENTS.md, decision rights).
- **Wire behaviour of a conforming frame or packet does not change in a minor or patch release.** Nothing in the release tooling checks this by itself. What constrains it is that a released test vector is never edited, only superseded ([07](../../07-test-vectors.md)), so a change of conforming output fails a released vector, and that the maintainer, who cuts every release, reads the changes of the release against this rule.
- **A fix of a deviation from a Blue Book is called out.** Its pull request is titled `fix(blue-book): …` ([pr-body.md](../../process/pr-body.md)), and `cargo xtask changelog` lists it under "Deviations fixed" of the release section (`file:xtask/src/changelog.rs`, the `Deviations fixed` section and the unit test of two `blue-book` titles). The coordinator runs it at a release, and `CHANGELOG.md` is never edited by hand.

What the record does not establish: that a future release follows the policy. That is read again at each release by the maintainer, and at v1.0 when the major version changes.

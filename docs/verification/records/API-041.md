**Review of the frame codecs' configuration types** (2026-10-25, branch `m2/hc-tests`, prepared by an agent, pending exit review). The question is the text of API-041: plain data, no references to external state, so that a configuration can be serialized, compared, and placed in read-only memory. Read in `crates/aldis-{tm,tc,aos,uslp}/src/config.rs`:

| Crate | Types | Result |
|---|---|---|
| `aldis-tm` | `TmPhysicalChannelConfig`, `TmVirtualChannelConfig`, `DataFieldContent` (`Copy`); `TmMasterChannelConfig` (`Clone`, with an array of eight `VcEntry`, each a `TmVirtualChannelConfig` and a `FrameLayout` of seven `Range<usize>`) | Plain. No reference, lifetime, `Box`, `Vec`, `dyn`, or interior mutability in a field. `PartialEq`, `Eq`, `Hash`, `Debug` derived. `new` of the physical channel, the VC builders (`with_fsh`, `with_ocf`, `with_security`), and `TmMasterChannelConfig::new` are `const fn` |
| `aldis-tc` | `PhysicalChannelConfig`, `VcConfig`, `MapConfig`, `SegmentHeaderUse` (`Copy`); `VcTable<V, M>` (`Clone`, two arrays of `Option`) | Plain, as above. The constructors of the three `Copy` types are `const fn` |
| `aldis-aos` | `AosPhysicalChannelConfig`, `AosVirtualChannelConfig`, `AosEdition`, `DataFieldContent` (`Copy`); `VcTable<N>` (`Clone`) | Plain, as above. The constructors and builders of the `Copy` types are `const fn` |
| `aldis-uslp` | `PhysicalChannelConfig`, `VcConfig`, `VcParams`, `MapConfig`, `TransferFrameType`, `OcfUse`, `SecurityScope`, `TruncatedFrameLen` (`Copy`); `VcTable<V, M>` (`Clone`) | Plain, as above. The constructors of the physical channel, the VC, and the MAP are `const fn` |

The tables `VcTable` (TC, AOS, USLP) and the TM master channel's `with_vc` build their arrays by a validation that loops, so they are constructed at run time and cannot be a `const` or `static`; they are values that clone, compare, and print, and a mission that wants them in read-only memory builds them once at start-up. The four `crates/aldis-*/tests/config_contract.rs` check the property by what a test can observe: each type satisfies `Copy`/`Clone + PartialEq + Debug + Send + Sync + 'static` (a type with a borrowed field would not be `'static` generically), and the TC and USLP physical channels, VCs, and MAPs fill a `static`.

Two things the review found and leaves open, for the maintainer through the coordinator:

1. `TruncatedFrameLen::new` and `get` (`crates/aldis-uslp/src/config.rs:157`, `:167`) are not `const fn`, though the check they make (a range of 6 to 32) is const-evaluable, so a `VcParams` with a truncated frame length cannot be built in a `static`. RS-012 asks for const construction "where the validation is `const`-evaluable".
2. `VcParams` has public fields (`crates/aldis-uslp/src/config.rs:176`–`189`), against the wording of RS-012 ("private fields"). It is the record of the parameters that `VcConfig::new` validates, and `VcConfig::params` returns a copy, so a changed copy does not change the VC (`config_contract.rs::a_configuration_cannot_change_after_construction`); but the type is a configuration that can hold a value `VcConfig::new` would reject.

scrambled segments never panic or wedge the reassembler, and every outcome is consistent), and `spp_time_header` (the time split never panics under any CUC or CDS layout; a split time code lies in the secondary header, carries the configured time code ID, and re-encodes its T-field exactly). `aldis-ffi`: `ffi_decode` (the C ABI decoders of SPP, EPP, and time, `peek_length`, the P-field parser, and the ASCII parser agree with the Rust ones on the same octets in both modes: the same fields, offsets, lengths, and anomaly flags, or the same status and detail, also when the detail has only its fixed prefix; a decoded time code re-encodes through the C ABI to the Rust encoder's octets; and, from M2 WP-1, the C ABI of `aldis-core`: `aldis_crc16` agrees with `crc16`, `aldis_ocf_classify` with `Ocf::decode` on four octets and rejects any other length, `aldis_ocf_check` with the checked report constructors with the same status and detail, and both forms of the OID generator fill the input's length with `OidGenerator::fill`'s octets).

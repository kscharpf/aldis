# Milestone AINT — Interoperability

**Goal:** the A3 Rust flight node exchanges TM frames, TC frames, and COP-1 with an independent ground system that runs as a black box. FOP-1 is on the ground system's side, FARM-1 on the flight node's. The two are joined by a transport driver outside the crates that steps the node against a socket and a clock. The driver is the only new I/O; the crates stay sans-I/O (GEN-030–032). The nominal case and the lossy-link case of A3 must pass against the independent implementation, and every discrepancy is filed as an open issue or reported upstream by the maintainer. The milestone gates no release.

### WP-1 Interoperability profile (S) — area APP, no code

### WP-3 Spike: TM into the ground system (S)
Parallel with WP-2 once its binary sends frames. A TM-only run: the A2 and A3 flight node's frames reach the ground system's TM link (D1 c), which decodes them (frame header, FECF, VC demultiplexing, the Space Packets of the HK, event, payload, and dump applications, the OCF as a CLCW). The ground system's mission database (WP-4) is not needed for frame-level decoding. Every difference between what the ground system shows and what [§4.1, §3](../reference-application.md) says is a discrepancy, classified as in D2 (d) and filed. The spike's notes feed the loss script of WP-1. The build and run script `scripts/interop-yamcs` lives in `scripts/` because the `shell` check (VER-071) refuses tracked shell files elsewhere.
- **Done when:** every discrepancy is an issue (or a row of [09](../09-open-issues.md)), listed in §6, or the spike found none and says so.

## 5. Risks

| Risk | Mitigation |
|---|---|
| The licence reading is wrong: AGPL-3.0 obligations fall on this repository, or reading the ground system's source becomes tempting during a diagnosis | D2: the maintainer accepts D1 on the checks of D1 (a); the ground system stays in a separate process and an image outside the repository; the agents diagnose from the wire, the logs, and public documentation, and stop and ask the coordinator when that is not enough |
| The ground system's COP-1 does not offer a parameter the profile fixes (K, T1_Initial, Timeout_Type, the *Initiate AD Service* variant), or it expects a marker or coding that APP-006 excludes | D1 (b) and (c) are checked before acceptance; a missing parameter is a discrepancy of the profile: the case is run with the nearest setting and the difference is recorded, or the maintainer decides to change the profile (a scope decision) |
| Real time makes the lossy-link case flaky: a loss script by unit index hits different units on a different schedule | D6 judges facts, not the schedule; the indexes are chosen against the schedule the spike observed (WP-3) and the criteria name the FARM-1 cells to reach; the driver's own tests run in virtual time (D5 c) |
| Interoperability finds a defect of the Aldis crates | A track-R pull request with a regression vector (roadmap §6 rule 5), filed from WP-4; the milestone does not wait for it when the case fails for a filed reason (the exit asks for filed discrepancies, roadmap §3) |
| A discrepancy of the other system's is a deviation from the Blue Book that cannot be told from an Aldis reading | The Blue Book decides (AGENTS.md "Sources of truth"); a reading the normative text does not settle is an OI for the maintainer, never settled in code |
| The ground system needs a dependency in the driver (an HTTP client) or a service in CI | D4 keeps the driver standard-library only and runs the ops script from the ground system's side; D8 keeps it out of the merge gate; both need the maintainer's decision before they change |
| A fix for the ground system's sake changes a golden trace of A3 | The driver and the profile change no node (D5); a change of a node is a track-R or an A3-level change by its own plan, and APP-004 and APP-005 hold |

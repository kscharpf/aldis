# C ABI profile

This profile defines the C interface. The Rust reference implementation exposes it through `aldis-ffi`, and the native C++ and C implementations SHALL expose the same interface. Because both expose one interface, a C or C++ application can link either library without source changes.

**Terms and acronyms:** see the [glossary](../glossary.md).

**Panic handler** (OI-49). No panic path is reachable in the library (GEN-020, VER-010). The static library of a `no_std` target built with the `panic-handler` feature nevertheless defines `#[panic_handler]`, so that it links; if it ever runs, it executes a trapping instruction (`core::arch::asm!`, the one `unsafe` block of the handler, GEN-070) and only then spins: `udf #0` on Arm (thumbv7em, armv7r), `ebreak` on RISC-V (riscv32imac), `brk #0` on AArch64, `ud2` on x86. The trap raises the target's undefined-instruction or breakpoint exception, so the fault handler, a debugger, or a watchdog sees the failure where it happened, and the handler adds no undefined symbol (CABI-004). On a target where `asm!` is not stable, such as SPARC V8 (LEON3), the handler only spins, and a watchdog is the integrator's means to end it. The exerciser's `panic-unreachable` handler (VER-010) is another handler and unchanged.

## 5. Memory model

Engines and stateful helpers are placed in **caller-owned storage**. No heap is used. The storage is a typed struct of `uint64_t` words that the caller declares as an object of that type, so the C compiler supplies its size and alignment and no length crosses the ABI (OI-57 convention 4). The pointer to the object is the handle.

The words belong to the library: a C caller never reads or writes them. The word count of each type is one `pub const` in Rust, and a compile-time check proves that the helper's state and its tag fit it on every supported target.

| ID | Requirement | Source | Verif. |
|---|---|---|---|
| CABI-030 | Engine capacities (const generics in Rust) SHALL be fixed when the library is built. They SHALL be read from a build configuration file (`aldis-ffi/capacities.toml`) and emitted as `ALDIS_*_MAX_*` constants in the header. The header is the only report of them; there is no run-time query. | GEN-011 | A |
| CABI-031 | The storage of a stateful helper SHALL be a typed struct of `uint64_t` words that the caller declares, and `*_init` SHALL take a pointer to it, with no storage length. The build SHALL fail when the helper's state does not fit the struct. `*_init` SHALL fail with `ALDIS_ERR_INVALID_FIELD` for `NULL` or a pointer misaligned for its type (CABI-022). `*_init` SHALL NOT read the storage first: it replaces whatever the storage holds, because the tag of live storage cannot be told from the garbage of an uninitialized object. | — | T |
| CABI-032 | A handle SHALL carry a magic/generation tag. Calls with a deinitialized or foreign handle SHALL fail with `ALDIS_ERR_INVALID_HANDLE` where detectable. | — | T |
| CABI-033 | Withdrawn: configuration and detail structs carry no `struct_size` (OI-57 convention 5). The ABI major version (CABI-060) is the only compatibility mechanism; while it is 0, an incompatible change to a struct bumps the minor version. | — | — |

## 6. Engines as step calls, without callbacks

An engine call is the step function of [03 §5](../03-api-model.md#5-engines-the-sans-io-contract) behind a handle. It accesses the engine's state **in place**, in the caller's storage, as `&mut` for the duration of one call, and uses the `decide`/`commit` form that API-058 permits, so a failed call leaves the state unchanged without a copy of the state on the stack (FOP-1's state is at least 16 KiB, against the 10 240-byte stack budget of the C ABI; OI-45, OI-57). The handle's tag check (CABI-032) is the one of `handle.rs`, whose `Handle::read` and `Handle::update` lend the state in the storage to a closure as `&T` and `&mut T` and make no copy of it; the closure is the whole engine step, and `update` takes the handle by `&mut`, so that no second reference to the state exists through that handle during the step. `update` has no rollback: the closure calls `decide` and then `commit`. The reference aliases nothing else only if the caller serializes calls on the storage (CABI-050) and no buffer of the call overlaps it; the output area is checked against the storage (CABI-022), but an input buffer is not yet (§12 item 3) (GEN-071). No engine has a C module yet; the stateless-by-value helpers of §3 to §5 are small and may still use `load` and `store`. The conventions of [§12](#12-conventions-adopted-2026-10-29-implementation-pending) (flat input structs, flat action structs, ranges) apply.

## 10. Details settled for the M1 codecs

The C ABI of `aldis-time`, `aldis-spp`, and `aldis-epp` ([M2 plan](../milestones/m2-frame-codecs.md) WP-0c) settles these details of the rules above, following D4 and D5. The frame codecs and the engines follow them.

- **Status codes** (CABI-020; OI-57 convention 3): a function returns a `uint32_t`, `ALDIS_OK` (0) or `ALDIS_ERR_<KIND>`, whose value is the catalogue code of the kind, so that a too-short prefix returns `ALDIS_ERR_INCOMPLETE` (2, M2 plan D14) and `aldis_error_detail_t::kind` equals the status. The constants are the enumerators of `aldis_status`, a mirror enum (§10 "Flags and enumerations") that no return type of the header uses. `cargo xtask status --write` generates it (`src/status.rs`) from the error catalogue of 03 §9, with a `const _` assertion per row that the constant equals `ErrorKind::<Kind>.code()`, so a code that differs from `aldis-core` fails the build; a test checks that every `ErrorKind::ALL` entry has its constant, in order, and the header test checks the enumerators against the committed header. The negative convention, the negated `status`, and the parenthesized `#define`s are gone.
- **Detail** (CABI-021): `aldis_error_detail_t` is `{ uint32_t kind; uint16_t field; uint16_t detail; uint64_t needed, expected, found; }`, 32 octets. The library writes the whole struct, only when the call fails; a misaligned pointer fails the call before it does anything. `kind` is the catalogue code, the status the call returns, `field` the field code of 03 §9.1 or 0, and `detail` one of `ALDIS_DETAIL_NONE`, `_NEEDED`, `_EXPECTED`. The field codes are published as `ALDIS_FIELD_*` constants, generated from the catalogue.
- **Argument checks** (CABI-022): `NULL` is allowed for a buffer of length 0 and for the detail; any other `NULL`, a pointer misaligned for its type, a buffer range that wraps or exceeds `PTRDIFF_MAX`, an output buffer that overlaps an input buffer of the same call or a helper's storage, and an enumeration argument with no constant are each `ALDIS_ERR_INVALID_FIELD` with field 0 and no detail. A misaligned detail pointer fails the call before it does anything.
- **Configuration structs** (CABI-033, withdrawn): a configuration struct is a plain struct with no size member; the library reads exactly the struct the header declares, so caller and library must be built from the same header version (CABI-060). A struct embedded in another (a time code format inside a secondary header layout) is part of it. The capacities are the `ALDIS_*_MAX_*` constants of the header (CABI-030).
- **One-shot encoders** (D4, API-020, API-023; OI-57): the C ABI has no two-phase writer. A frame or packet is built in one call, `aldis_<std>_encode`, that takes every variable field and keeps no state; an Only Idle Data frame by `aldis_tm_encode_oid`, `aldis_aos_encode_oid`, or `aldis_uslp_encode_oid`, which take an `aldis_oid_generator_t`. The earlier `_writer_begin` and `_writer_finish` functions (OI-50) are removed. A frame codec whose one-shot encoder has no field for the Security Header and Trailer (TC, USLP) writes zeros there (API-072); a caller that applies SDLS through the C ABI uses TM or AOS, or a later encoder variant.
- **Flags and enumerations** (CABI-010): flags in input structs are `uint8_t` 0 or 1; flags in output structs are `bool`. Enumerations are `uint8_t` or `uint32_t` fields with `ALDIS_*` constants (OI-57 convention 2). Each enumeration is a fieldless Rust enum of the same width, `aldis_<std>_<noun>`, whose variants are named for the constants (`ALDIS_TC_FRAME_AD`); cbindgen emits them as the enumerators of a C `enum` of that name, which no field uses, so a value from C is never an enumeration type. `mirror::parse` (`src/mirror.rs`) turns the integer into the Rust enum, the only place where an out-of-range value is rejected (`ALDIS_ERR_INVALID_FIELD`), and an exhaustive `match` with no wildcard arm converts it to the core type. The enumerations are closed sets of values; an open registry (the `ALDIS_USLP_UPID_*` and `ALDIS_EPP_EPI_*` values), a bit mask (`*_ANOMALY_*`, `*_SUBSET_*`), a limit, and a length stay plain constants.
- **Time codes** (D4): one flat format struct and one flat value struct for CUC, CDS, CCS, and agency-defined codes, selected by `code`. CUC fine time is `uint8_t fine[10]`, left-aligned, with `fine_len`; octets from `fine_len` on must be 0. A reserved time code ID decoded in lenient mode is `ALDIS_TIME_UNKNOWN`, with its P-field and no value; it cannot be encoded through the C ABI. Conversions go directly between CDS, CCS, and ASCII (`aldis_time_convert`); the intermediate UTC instant does not cross the ABI.
- **Stateful helpers** (D5, CABI-030…032; OI-57 convention 4): the storage is a typed struct, `aldis_spp_tracker_t`, `aldis_spp_segmenter_t`, `aldis_spp_reassembler_t`, or `aldis_oid_generator_t`, each a `uint64_t words[ALDIS_*_WORDS]`, which the caller declares as an object of that type; the sizes hold on every supported target. `_init(storage, …, err)` takes a pointer to it, which is also the handle, and fails with `ALDIS_ERR_INVALID_FIELD` for `NULL` or a misaligned pointer. The storage starts with a tag: a magic number per helper, the layout generation, and the storage's own address; a call fails with `ALDIS_ERR_INVALID_HANDLE` when the tag is not that of its helper at that address, which detects uninitialized, released (`_deinit`), foreign, and copied storage. A `NULL` handle is `ALDIS_ERR_INVALID_FIELD`. `_deinit` returns nothing and ignores an invalid handle. Buffers are passed on every call and never stored (API-060): the segmenter takes the same SDU on each call (another length is `ALDIS_ERR_LENGTH_MISMATCH`), and the reassembler the same reassembly buffer. The tracker's capacity is a build-time maximum, `ALDIS_SPP_TRACKER_MAX_APIDS` (`capacities.toml` `[spp]`), and its configuration chooses a capacity up to it.

## 11. Details settled for the frame codecs

The C ABI of `aldis-tm` ([M2 plan](../milestones/m2-frame-codecs.md) WP-2 module 7, #94) settles these details for the frame codecs, following D14. The C ABI of `aldis-tc`, `aldis-aos`, and `aldis-uslp` follows them (maintainer decisions 2026-10-24).

- **Arrays of configuration structs**: an array of configuration structs, such as the virtual channels of a master channel, is a C array: a pointer and a count, the stride being `sizeof` of the struct. The pointer must be aligned for the struct, and the array must not wrap the address space or exceed `PTRDIFF_MAX`; otherwise the call is `ALDIS_ERR_INVALID_FIELD`.
- **Master channels**: a master channel configuration embeds its physical channel configuration as a struct, as the Rust constructor takes it. A call that needs the per-VC configuration takes one master channel; a caller with several master channels on one physical channel reads the SCID with the header decoder first. The Rust lookup over several master channels has no C form.
- **Security-layout lookups**: the `_with` pairs exist only for decoders. A decoder without a suffix takes the physical channel configuration alone and decodes as on a channel without SDLS; its `_with` variant takes the master channel configuration and the security layout of each virtual channel from it. A call that takes a master channel, validation among them, always uses its layouts. There is no lookup-mode argument.
- **Frame contents**: a one-shot frame encoder takes the frame's variable fields (TM: the Secondary Header data, the Security Header, the data field, the Security Trailer, and the OCF) as `(const uint8_t *, size_t)` members of one content struct (`aldis_tm_content_t`), read once per call and never kept (API-060). Each member pair is checked as a buffer argument is (CABI-022): `NULL` only with length 0, and no overlap with the output buffer. The virtual channel array stays a pair of arguments; no configuration struct holds a pointer.
- **Stateless finish of a writer that zero-fills**: Withdrawn (OI-57). The C ABI has no `_writer_finish`, and the Rust `resume` it called is removed.
- **Decoders that need the channel table** (TC, AOS, USLP; maintainer decision 2026-10-24): when a codec's decoder cannot run without its channel configuration, the codec has one decoder with no `_with` suffix, which takes the channel configuration and always uses its security layouts; so do its validation and its encoders. `_with` pairs exist only where a decoder can also run on the physical channel alone (TM).
- **Validation reasons** (TC-021, USLP-014): a validation call reports why a frame was rejected through a separate `uint32_t *reason` out-parameter, with `ALDIS_<STD>_REASON_*` codes: 0 (`_REASON_NONE`) on success, the reason code on a rejection, whose error the call also returns, and unchanged on a configuration or argument error. The reason does not travel in `aldis_error_detail_t`.
- **Delimiters** (TC-020, USLP-015): a delimiter is a stateless call that takes the whole data unit and an offset (`aldis_<std>_next_frame(unit, unit_len, offset, …, out, err)`, with the channel arguments after `offset` where the codec needs them) and returns the next item's kind (a `uint8_t`), its range (`aldis_range_t`: offset and length), and declared length (`len` for a frame, more than `len` for one cut short, 0 otherwise); the kind is `ALDIS_<STD>_DELIMITED_END` when nothing remains. The caller loops, adding each item's length to the offset.
- **Truncated USLP frames** (USLP-002; OI-48, OI-52): the C view of a decoded truncated frame, `aldis_uslp_frame_t`, has `truncated` true and `kind` `ALDIS_USLP_KIND_EXPEDITED`, since Annex D1.3.1 note 3 makes a truncated frame expedited user data, so that a caller that ignores `truncated` still routes it as the Blue Book says; the members only a full frame has (`ocf_flag`, `vcf_count_len`, `vcf_count`, `has_fecf`) stay 0 or false. A VC with a truncated frame length carries only truncated frames: the encode calls reject a non-truncated frame on it with `ALDIS_ERR_INVALID_FIELD` (`end_of_frame_primary_header_flag`), the decode, validate, and peek-length calls reject one with the same error (validation reason `ALDIS_USLP_REASON_NON_TRUNCATED_FRAME_NOT_ALLOWED`, 18), and the delimiter reports `ALDIS_USLP_DELIMITED_NON_TRUNCATED_NOT_ALLOWED` (5), discarding the rest of the data unit.
- **TM frame length** (TM-001; OI-51): `aldis_tm_config_check` and every call that takes a physical channel reject a frame length above 4 095 octets with `ALDIS_ERR_INVALID_CONFIG` (`frame_len`, `expected` 4095), since the CRC-16 misses some double-bit errors beyond it (VER-064).
- **Empty channel table** (TC-024, AOS-020, USLP-017; OI-55): `aldis_tc_mc_config_check`, `aldis_aos_mc_config_check`, `aldis_uslp_vc_table_check`, and every call that builds the channel table from a VC array reject `vc_count` 0 with `ALDIS_ERR_INVALID_CONFIG` (`vc_id`). A physical channel with no virtual channel has no Spacecraft ID to accept an OID frame for.
- **Channel shapes**: a codec whose Rust configuration has a master channel type passes the master channel, which embeds its physical channel and carries the SCID: TC with separate arrays of VC and MAP structs, AOS and TM with an array of VC structs whose structs carry no SCID. A codec whose Rust configuration has no master channel type (USLP, whose `VcTable` spans every master channel of the physical channel) passes the physical channel configuration with flat arrays of VC and MAP structs, each tagged with its SCID, as the Rust constructor takes them.

## 12. Conventions adopted 2026-10-29 (implementation pending)

The maintainer decided seven conventions for the C ABI on 2026-10-29 (OI-57; decision log). The project is pre-release, so backward compatibility of the C ABI is not a constraint, and the goal is the simplest C ABI that keeps the high-assurance properties. **The code implements items 1 (one-shot encoders), 2 (enumerations), 3 (status codes), 4 (typed storage), 5 (no `struct_size`, no `aldis_limits`), the `handle.rs` mechanism of 6 (in-place state), and the `aldis_range_t` part of 7 (views); what remains is the engine modules, which build the rest of 6 and 7 (actions) into their calls.** Until then, a row of §3 to §5, §8, §10, or §11 that this section changes describes the code that exists and stays as written: it is the as-built behaviour, and this section is what the implementing pull request makes true. Each implementing pull request rewrites or withdraws the rows it changes, in the same change as the code. The engine rows (CABI-040 and the introduction of §6) have no engine module yet and are rewritten now; the in-place state mechanism they rely on exists.

|---|---|---|

Frames and packets are built with the one-shot encoders (`aldis_tm_encode`, `aldis_tc_encode`, `aldis_uslp_encode`, `aldis_uslp_encode_oid`, `aldis_spp_encode`, `aldis_epp_encode`, …), plus a one-shot Only Idle Data encoder for TM and AOS where one is missing. ### 12.3 Spikes (2026-10-29, throwaway, not committed)

Run with cbindgen 0.29.4 and the language, `[export]`, and `[enum]` settings of `crates/aldis-ffi/cbindgen.toml` (`language = "C"`, `cpp_compat`, `style = "type"`, `usize_is_size_t`, `prefix_with_name`, `rename_variants = "ScreamingSnakeCase"`), on a scratch crate. None contradicts a decision; points for the implementing pull requests are marked **Open point**.

**Spike 1: `#[repr(u32)]` fieldless enum.** `#[repr(u32)] pub enum aldis_kind_t { Alpha = 0, BetaGamma = 7 }` is emitted as an `enum` with a fixed underlying type under C23 and C++, plus, in C before C23, a `typedef uint32_t`.

So in C99 a field of the type is a `uint32_t` (fixed width, never `int`-sized), and the constants are enumerators of an `enum` that no field uses. `prefix_with_name` makes each constant `<TYPE NAME>_<VARIANT>` with the type's `_t` inside (`ALDIS_KIND_T_ALPHA`). **Settled (the enumeration-glue pull request, item 4):** a Rust variant carries the full name of its constant (`ALDIS_TM_POINTER_STARTS_AT`), and the enum is annotated `cbindgen:prefix-with-name=false` and `cbindgen:rename-all=None`, so cbindgen emits the variant as written. The type is named `aldis_<std>_<noun>` with no `_t`, and no field uses it. A variant name with a digit needs the underscore in Rust itself (`ALDIS_TIME_CDS_DAY_16`), because cbindgen would otherwise write `DAY16`. cbindgen emits an enum only if a signature names it, so `cbindgen.toml` lists every mirror enum under `[export] include`. The header stays valid C99 and C++11 (CABI-003), and the `c-smoke` check compiles it once as C23.

**Spike 2a: typed storage.** `#[repr(C)] pub struct aldis_x_t { pub words: [u64; N_WORDS] }` with `pub const N_WORDS: usize = 4;` is emitted as a struct. The array length keeps the constant's name, and the constant becomes a `#define`. **Open point:** a length that is an arithmetic expression of constants (`(FRAMES * FRAME_LEN + FRAMES * 2 + 8) / 8 + 1`) made cbindgen emit the type as an opaque forward declaration (`typedef struct aldis_fop1_t aldis_fop1_t;`) with no body and no warning. The word count of each storage struct must therefore be one `pub const` (computed in Rust, with a `const` assertion that the state fits), and the implementing pull request checks the generated header for the body of every storage type.

**Spike 2b: `#[repr(C, u32)]` enum with payload variants.** Variants `None`, `Transmit { range: aldis_range_t, vc: u8 }`, and `Event { code: u32 }` are emitted as a tag enum, one body struct per variant, and a struct of the tag and an anonymous union.

`aldis_range_t` is `typedef struct { size_t offset; size_t len; } aldis_range_t;`, and a fixed array of the union in a struct is `aldis_action_t actions[3];`. cbindgen therefore emits the shape of convention 7. The union is **anonymous**, which is C11 (a GNU extension in C99), and CABI-003 requires valid C99. **Settled (maintainer, 2026-10-29):** the header stays C99, so convention 7 uses flat action structs and no union crosses the C ABI.

**Spike 3: stack use of in-place access.** A scratch crate on `thumbv7em-none-eabihf`, release profile with `opt-level = "s"` and `panic = "abort"`, holds a 16 420-octet state (16 frames of 1 024 octets, 16 lengths, a head counter) in `aldis_fop1_t { words: [u64; 2053] }`. Two `extern "C"` functions run the same `push` of a frame:

- `inplace(s: *mut aldis_fop1_t, …)` casts to `&mut State` and calls `push`. Its own frame is 8 octets (`push {r7, lr}`) and it ends in a tail call to `push`, which saves 20 octets (`push {r4-r7, lr}`) and has no local frame. **Worst case about 28 octets.**
- `byvalue(s: *mut aldis_fop1_t, …)` does `ptr::read` of the state, calls `step(self, …) -> (State, u32)`, and `ptr::write`s the result back: the by-value form of the former CABI-040 wording. Its frame is 32 octets of saved registers plus `sub sp, #32768` and `sub sp, #80`, so **32 880 octets**; `step` adds 24 and `push` 20: **worst case about 32 924 octets**, two copies of the state and over three times the 10 240-byte budget.

The numbers are the frames in the compiler's assembly (`cargo rustc --release --target thumbv7em-none-eabihf -- --emit=asm`), summed along the deepest call path; they were not taken with `cargo xtask stack`, which builds the workspace with `-Z build-std` on the tooling nightly and does not see a scratch crate. The pull request that adds the first engine module (FARM-1 or FOP-1) measures the real engine with `cargo xtask stack`; the in-place mechanism landed first, and its unit test shows that the closure sees the state at its address in the storage, with a 16 KiB state. In-place access in the spike used about 28 octets of stack whatever the state size; by-value access could not hold FOP-1 at its default capacity at all. Whether a real engine call fits the budget is unmeasured until the first engine module lands.

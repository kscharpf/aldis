# Briefing an agent

For the coordinator who dispatches an agent, and for the agent. A dispatched fork or subagent inherits [AGENTS.md](../../AGENTS.md); this file holds the conventions AGENTS.md does not carry. A brief names the task and links here. Reasons and dated incidents behind these rules: [history.md](history.md).

## The brief

Name the goal, the base, what done means, whether the round is final, whether the agent has the gate, and what the agent leaves alone: other pull requests, other tracks' directories ([roadmap §6](../08-roadmap.md)). Title the pull request of a work package `feat(m3/wp-4): Implement …` ([pr-body.md](pr-body.md)). Add what the agent cannot find in the repository: a decision already made in chat, a measurement to compare against, a pull request to stack on.

## Conventions for the agent

1. **Worktree.** Work in `.claude/worktrees/<branch>`, the path `scripts/reverify` and `scripts/cleanup-merged` expect, created from a fresh `git fetch origin`. The search boundary of AGENTS.md says what to search, not where to create a worktree. `.claude/settings.json` sets `NO_COLOR`, `GH_FORCE_TTY`, and `GH_NO_UPDATE_NOTIFIER` for every command; `cd` to a literal absolute path, since a path computed at run time is refused by the permission check. The Bash tool runs zsh on macOS: write `${B}:path`, not `$B:path` (zsh reads `:c…` as a modifier); macOS has no `timeout`, so bound a run with the tool's `timeout` parameter; edit in place with `sed -i ''` (BSD) or `perl -pi -e`. Put temporary files in the session scratchpad. Hooks refuse an Edit, Write, or NotebookEdit on a file in the base checkout outside `.claude/worktrees/` (the coordinator included), and a command that detaches a process: a background `&`, `nohup`, `disown`, or `setsid` (item 2).
2. **Waiting.** Start a command that runs longer than a minute (`cargo xtask check`, `scripts/reverify`, `gh run watch <id> --exit-status`) with `run_in_background`, and wait for its completion notification: it arrives when the command exits, and its output file holds the result. While it runs, work on something else or make no tool call. Do not write a poll loop (`until grep …`, `perl -e 'alarm …'`, `while pgrep …`), do not `sleep`, do not use Monitor as a wait, and do not read the output file while you wait. A turn that ends while work is pending notifies the coordinator, who must answer it, so end the turn with the final report only.
   - **No check before your first edit,** except a baseline the brief asks for.
   - **Three tiers of `cargo xtask check`** (VER-068): `--quick` while editing (about a minute, every error at once); the default in the rounds that run the PR's check tier (it stops at the first failure); `--full` is optional, never required. The run prints what it skipped and how to install a missing tool, and ends `check: quick tier ok (not a gate pass; …)`, `check: default tier ok (not a gate pass; …)`, or, for `--full`, `check: passed (full tier; …)` (`passed with skips` when a tool is missing). Report which tier passed, never "check passes" alone. Coverage lowers a waiver count above the measured misses and prints `shrunk: …`: commit the edit (the gate fails on any mismatch); a count below the misses fails and is a reviewed edit. A coverage failure lists the missed lines as `path:line`; rerun one crate with `cargo xtask coverage -p <crate>`.
   - **One `cargo xtask check` at a time.** Wait for the first run's notification. Never `pkill` or kill a run to start another.
   - **Resume after a failure.** `cargo xtask check --from <step>` skips the steps before the named one (the names it prints). Its last `check: partial` line says `not a pass`; the exit code is not the pass signal. After the fix, finish with a whole run of the tier you are reporting before you report that it passes.
3. **Gate.** The last run before you push (after merging `origin/main` too) depends on the round. **The PR's check tier** is the default `cargo xtask check`. It runs in the first round, before the PR is opened, and in the final round: the round after the last review, which the coordinator's brief names as final; that run's findings are fixed in the same round. An intermediate fix round, and a merge-only round (merging `origin/main` and resolving conflicts, no other change), run `cargo xtask check --quick` plus `cargo test` of the crates or workspaces the round changed. A final review that asks for nothing needs no further run. The train's verify still decides the merge. Then push, and stop: the coordinator hands the reviewed pull request to a merge train ([coordinator.md](coordinator.md#merge-trains)). A brief that gives you the gate says so; then merge `origin/main`, re-run `cargo xtask check`, push, run `scripts/reverify --alone <pr>` (flags and exit codes: `scripts/reverify --help`; rules for waiting on it: [coordinator.md](coordinator.md#verification)), and confirm `cargo xtask verify check`. When `main` moves during the work, merge it again before the final run.
4. **Pushes.** Confirm the pull request is open (`gh pr view <n> --json state`) before every push to its branch. Read the last line of the check run you report before you push (`… tier ok (not a gate pass; …)`, or `check: passed …` for `--full`; item 2), not a tailed log.
   - **A refused command.** When a guard, a hook, or the permission check refuses a command, stop and put its exact message in the report. Do not reach the same end another way. Editing a file inside your own worktree with the Edit tool is the ordinary way to change it, not a way around a refused command.
   - **A hung `shell` step.** When the `shell` step runs over 15 minutes, stop the run and run the steps after it with `--from` (their names are the ones the run prints, such as `xtask header`). The tier has then not passed: report the steps that passed, that `shell` (VER-071) did not finish, and the hang, and leave `shell` to the gate.
5. **Clean the build directories.** After the final push of a round, run `cargo clean` in your worktree, and in each separate workspace you built there that has its own `target/` (`exerciser/`, `fuzz/`, `crosscheck/`, `refapp/`), whether or not the pull request has merged (maintainer, 2026-11-07). A later fix round rebuilds.
6. **Boundaries.** Stop at an open pull request, with a published record when the brief gave you the gate (a pull request that rides a train needs none). Merging is the maintainer's. Leave other pull requests alone, and leave the worktree in place: the coordinator removes it after the merge.
7. **Measurement.** Measure on a throwaway branch: one full run of every check, the branch and its worktree deleted after the results are read. The record notes the run publishes under `refs/notes/verify` stay.

## The reply to a review

The reply to a review (a pull request comment, point by point, ending in the marker of [AGENTS.md](../../AGENTS.md)) names the commit it answers, a hex prefix of the head of at least 7 characters: "Fix round, head 81db08a2". A pull request that rides a merge train is ready only while its latest reply names its current head ([coordinator.md](coordinator.md#merge-trains)); push again after the reply and the reply is posted again. The implementer posts the reply in the fix round itself, after the push, also when nothing changed (a finding deferred to an issue is answered with the issue's number); a fix round without a reply is not finished. After the third review no implementer is dispatched: the coordinator posts the reply ([coordinator.md](coordinator.md), "At most three reviews").

## The report

The pull request body follows [pr-body.md](pr-body.md). A round is finished only when its head is on the remote and has a pull request: before the final report, check that `gh pr view <n> --json headRefOid` gives your local `HEAD` (after a fix round, also the URL of the reply). A report about a check run alone, with no pushed head, is an interim note, not a report. End the report, once, with: the pull request URL; **Decisions met**, one line for each accepted plan decision or convention the work package implements, marked met or not met with the `path:line` that meets it; the evidence (command output, timings against the stated baseline, and the `verify check` result when you had the gate); **Judgement calls** (decisions the agent made under [decision-rights.md](decision-rights.md), each with its reason); **For the maintainer** (what only the maintainer can decide, as one question with a recommended option).

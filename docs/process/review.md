# Independent review

Protocol and requirements for independent review of pull requests on Aldis.

A reviewer of a pull request does **not** re-run the verification checks: `cargo build`, `cargo check`, `cargo test`, `cargo clippy`, `cargo fmt`, `cargo xtask ci`, coverage, the exerciser, fuzzing, or `cargo xtask verify`. They are the merge gate's job (VER-056…VER-058), and the gate already ran them on the head commit. Read the evidence instead: `cargo xtask verify check <head>` re-checks the published record, and a check that does not gate (`cpp-leon3`, `rust-sparc-leon3`) is read from the record, not assumed to pass. `kani` is nightly-only: a pull request's record shows it as not run ("nightly only (VER-059)"), and its results are in the nightly run on `main`, whose failure opens the nightly issue.

Spend the review on what no check covers: the reading of the Blue Book behind each decision (cite the clause), the requirements and whether the tests and vectors really cover them, the soundness of every `unsafe` block, the shape of the public API and C ABI, and the decisions and judgement calls the pull request lists. Read every suppression the change adds, because the gate passes *because of* it: each `#[expect(…, reason = "…")]` (RS-016), `// NOLINT(<check>): <reason>` (CPP-042), entry of `coverage-waivers.toml` (VER-024), and mutant triaged as equivalent in [mutants-triage.md](../verification/mutants-triage.md) (VER-025). Check that the reason is true and the region is the smallest one; a reason that does not hold is a finding. Report findings as [decision-rights.md](decision-rights.md) §2.6 describes, each with the file and line and why it matters; to show a defect, a failing test or vector case is the clearest form.

**Every `unwrap_or_default`, `.min(` used as a range bound, and `unwrap_or(0)`-style default that the diff adds on a wire-input path needs its proof,** and the reviewer reports each site without one. The proof is one of: an explicit error (`Incomplete`, `LengthMismatch`, `InvalidField`, `Malformed`); a length check that the reviewer can point to with `path:line`; or the allowed case of an absent optional or variable-length field, where an empty slice or 0 is the value. A clamp such as `start.min(len)..end.min(len).max(start)` that only satisfies `clippy::indexing_slicing` is none of these. No check finds the pattern, because telling a violation from an allowed use is a judgement call (maintainer, 2026-11-01); a clamp that only keeps a `copy_within` from panicking on a length it already proved is not a fallback. The rule is in [AGENTS.md](../../AGENTS.md).

**Every statement about the implementation cites the file and line it rests on** (`path:line`), quoting the code where the point depends on it, and a claim about a dependency, an algorithm, or a target names where it is in the code. A statement the reviewer cannot point to is not made. A review whose description of the code does not match the code does not count as a review of that pull request: the coordinator posts the corrections and the review is done again.

**Mismatches between documentation and code, or between two pieces of documentation, are reported together as one batch of nits at the end of the review.** The implementer fixes them in the same round as the code findings, so they cost no round of their own (OI-63).

# aldis-ffi

The C ABI of Aldis: a static and a shared library, `libaldis_ffi`, with the header [`include/aldis/aldis.h`](../../include/aldis/aldis.h) generated by `cbindgen`, for C and C++ applications and for bindings in other languages.

## Where it sits

The foreign-function boundary of the [architecture](../../docs/01-architecture.md) §2, above the layers. It depends on the facade `aldis` with the feature `full`, and builds as `staticlib`, `cdylib`, and `rlib`.

## Conventions

The [C ABI profile](../../docs/profiles/c-abi.md) sets the rules; §10 lists the details the M1 codecs settle.

- Every fallible function returns a `uint32_t`: `ALDIS_OK` (0) or an `ALDIS_ERR_*`, the code of the [error catalogue](../../docs/03-api-model.md#9-error-catalogue) (CABI-020). Its last parameter is an optional `aldis_error_detail_t *`, written only on failure, with the kind, the field code (`ALDIS_FIELD_*`, 0 for none), and `needed` or `expected`/`found` (CABI-021).
- Every pointer and length is checked: `NULL` only for an empty buffer or the detail, every pointer aligned, no output overlapping an input. A violation is `ALDIS_ERR_INVALID_FIELD` naming no field (CABI-022).
- Buffers are `(const uint8_t *, size_t)` in and `(uint8_t *, size_t cap, size_t *out_len)` out (CABI-011). Views are POD structs whose parts are `aldis_range_t` offset/length ranges into the input (CABI-012).
- The decode mode is a `uint32_t` (`ALDIS_MODE_STRICT`, `ALDIS_MODE_LENIENT`); anomalies are a `uint32_t` mask, bit `n` for the flag with index `n` (`ALDIS_*_ANOMALY_*`).
- There are no two-phase writers (OI-57): a frame or packet is built in one call, `aldis_<std>_encode`, and an Only Idle Data frame by `aldis_tm_encode_oid`, `aldis_aos_encode_oid`, or `aldis_uslp_encode_oid`; no call keeps a pointer (API-023, API-060).
- CUC fine time is `uint8_t[10]`, left-aligned, with its octet count; ASCII time codes are octet buffers without a NUL.
- A frame codec's channels (M2 plan D14): a master channel struct, which holds its physical channel struct, with an array of virtual channel structs and its count, so that no call takes a callback. Each array is a C array: a pointer and a count, the stride being `sizeof` of the struct, so caller and library must be built from the same header version (CABI-060). The `_with` decoders take each VC's Security Header and Trailer lengths from the master channel; their plain forms take the physical channel alone and decode as on a channel without SDLS; every other call that takes a master channel, validation among them, uses its layouts. A one-shot frame encoder takes the frame's variable fields as `(pointer, length)` members of one content struct (`aldis_tm_content_t`), each checked as a buffer argument is. TC ([`src/tc.rs`](src/tc.rs)): the master channel `aldis_tc_mc_config_t` holds the physical channel and the Spacecraft ID, with an array of `aldis_tc_vc_config_t` and an array of `aldis_tc_map_config_t`, each a C array with its count; the decoder, validation, and the encoder always use the layouts of the frame's VC or MAP (`TcFrame::decode` has no form without them, so there is no `_with` pair); the unified frame intake stream `aldis_tc_stream_next` fuses delimiting, fill removal, and channel validation into a single in-place pass, updating an in-out offset and writing an `aldis_tc_stream_item_t` with acceptance or discard details (`ALDIS_TC_DISCARD_*`); the CLCW crosses as a `uint32_t` word and the POD `aldis_clcw_t`.
- AOS (WP-4 module 8): a master channel `aldis_aos_mc_config_t` is one SCID with its physical channel; its VCs carry no SCID. The frame decoder `aldis_aos_decode` always takes the master channel, since each VC's Data Field Content is needed too, so it has no `_with` pair. The OID frames of VCID 63 are written by `aldis_aos_encode_oid`.
- USLP (M2 plan D12, D14): a USLP frame cannot be decoded without its virtual channel, so its calls take the physical channel struct with two arrays, of virtual channel and of MAP structs, each naming its SCID, as `VcTable::new` takes them; the table is built on every call with the capacities `ALDIS_USLP_MAX_VCS` and `ALDIS_USLP_MAX_MAPS`, and there is no `_with` pair. A full or truncated frame is one `aldis_uslp_frame_t` with a `truncated` tag. the unified frame intake stream `aldis_uslp_stream_next` fuses delimiting, fill removal, and channel validation into a single in-place pass, updating an in-out offset and writing an `aldis_uslp_stream_item_t` with acceptance or discard details (`ALDIS_USLP_DISCARD_*`), `ALDIS_USLP_STREAM_END` when nothing remains.
- The stateful helpers (`aldis_spp_tracker_t`, `aldis_spp_segmenter_t`, `aldis_spp_reassembler_t`, `aldis_oid_generator_t`) live in storage the caller declares as an object of that type, a struct of `uint64_t words[N]`, so the C compiler supplies its size and alignment. `_init` places the helper in it, and the pointer to the object is the handle; every call checks the tag `_init` wrote and fails with `ALDIS_ERR_INVALID_HANDLE` on uninitialized, released, foreign, or moved storage (CABI-032). The SDU and the reassembly buffer are passed on every call.
- The COP-1 engines (`aldis_fop1_t`, `aldis_farm1_t`) are handles of the same kind. Each input of the engine is one call, `aldis_fop1_step` or `aldis_farm1_step`, that takes a flat input struct with a `kind` field, the caller's clock in microseconds, and an output area, and fills a fixed-capacity `aldis_fop1_actions_t` or `aldis_farm1_actions_t` of flat action structs (`ALDIS_FOP1_MAX_ACTIONS`, `ALDIS_FARM1_MAX_ACTIONS`); the octets of a frame to transmit or an FDU to deliver are in the output area, and the action holds their `aldis_range_t`. `aldis_fop1_next_deadline`, `aldis_fop1_status`, and `aldis_farm1_status` only read. There is no `poll_*` call and no callback (CABI-040). FOP-1 builds TC Transfer Frames; its capacities are `ALDIS_FOP1_SENT_QUEUE_FRAMES` and `ALDIS_FOP1_MAX_FRAME_OCTETS`.

```c
#include "aldis/aldis.h"

aldis_spp_packet_t view;
aldis_error_detail_t err;
uint32_t rc = aldis_spp_decode(bytes, len, ALDIS_MODE_STRICT, &view, &err);
if (rc == ALDIS_ERR_INCOMPLETE) {
    /* err.needed octets are required */
}
```

## Files

- [`src/`](src/): one module per codec (`spp`, `spp_state`, `time`, `epp`, `tm`, `tc`, `aos`, `uslp`), per COP-1 engine (`fop1`, `farm1`), and per shared `aldis-core` module (`crc`, `ocf`, `oid`), the pointer checks (`abi`), the handle storage (`handle`), the status codes (`error`), and two generated modules: `field` (`cargo xtask fields --write`) and `capacities` (`cargo xtask header --write`).
- [`capacities.toml`](capacities.toml): the engine capacities fixed when the library is built, which become `ALDIS_*_MAX_*` constants in the header (CABI-030, GEN-011). Only the sections that have a C ABI are published: `[spp]`; `[tc]`, the MAPs one TC call takes (`ALDIS_TC_MAX_MAPS`); and `[uslp]`, the channel table of the `aldis_uslp_*` calls (`ALDIS_USLP_MAX_VCS`, `ALDIS_USLP_MAX_MAPS`).
- [`cbindgen.toml`](cbindgen.toml): the header generator's configuration (CABI-002, CABI-003).
- [`tests/vectors.rs`](tests/vectors.rs): every live case of `test-vectors/{time,spp,epp,tm,tc,aos,uslp}/` and of `test-vectors/core/{crc16,ocf,oid}.json` through the C ABI (M2 plan D4); [`tests/abi.rs`](tests/abi.rs): the argument, detail, and handle rules; [`tests/tm.rs`](tests/tm.rs): the TM channel arrays, security layout variants, and the OID encoder; [`tests/tc.rs`](tests/tc.rs): the TC channel and MAP arrays, the security layouts of a VC or MAP, the delimiter, the validation reasons, Control Commands, and the CLCW; [`tests/aos.rs`](tests/aos.rs): the same for AOS, with the FHEC and data unit decoders; [`tests/uslp.rs`](tests/uslp.rs): the USLP channel arrays and capacities, the tagged view, the validation reasons, the delimiter, and the OID generator handle; [`tests/c/smoke.c`](tests/c/smoke.c): a C program against the libraries.

## The header

`include/aldis/aldis.h` is generated, committed, and never edited by hand (CABI-002). The generator is `cbindgen` 0.29.4 (MPL-2.0), pinned in `xtask/src/header.rs` and installed by the verification image; `cargo xtask header` refuses another version.

```sh
cargo install --locked cbindgen@0.29.4
cargo xtask header --write            # regenerate after changing src/ or capacities.toml
cargo xtask header                    # check: what the verify check `header` runs
cargo xtask header c-smoke cc c++     # libraries built; the header as C99 and C++11 (CABI-001, CABI-003)
```

On a merge conflict in the header, merge the sources and regenerate ([M2 plan](../../docs/milestones/m2-frame-codecs.md) §3).

## Features

| Feature | Effect |
|---|---|
| `std` (default) | Hosted builds, for ground systems |
| `panic-handler` | A `#[panic_handler]` for `no_std` static-library builds. No panic path is reachable (GEN-020, VER-010), so it satisfies the linker; if it ever runs, it executes a trapping instruction (`udf` on Arm, `ebreak` on RISC-V, `brk` on AArch64, `ud2` on x86) and then spins. On a target without stable inline assembly (SPARC V8) it only spins (OI-49; c-abi.md §1) |
| `panic-unreachable` | A `#[panic_handler]` that calls the undefined `aldis_panic_is_unreachable`, for the exerciser's link check (VER-010). Not for integrators |

A bare-metal static library is built with:

```sh
cargo build -p aldis-ffi --no-default-features --features panic-handler \
            --target thumbv7em-none-eabihf --release
cargo xtask ffi-imports thumbv7em-none-eabihf   # needs nothing beyond memcpy/memset (CABI-004)
```

**LEON3 (`sparc-unknown-none-elf`, best-effort; OI-08).** The library builds on the tooling nightly with `-Z build-std=core` and `-C target-cpu=leon3`, and links with GNU ld for SPARC (rust-lld cannot). It deviates from CABI-004: the `compiler_builtins` in the archive refers to the SPARC quad-float routines `_Q_*`, which Aldis never calls. Link with `--gc-sections`, which drops them, or supply them ([CABI-004 record](../../docs/verification/records/CABI-004.md)).

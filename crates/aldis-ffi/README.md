# aldis-ffi

The C ABI of Aldis: a static and a shared library, `libaldis_ffi`, with the header `include/aldis/aldis.h` generated by cbindgen, for C and C++ applications and for bindings in other languages.

**Status:** skeleton. It exports no functions yet; it defines only the ABI version constants (CABI-060) and an optional panic handler for bare-metal builds. Each milestone adds the C ABI for what it implements: Milestone 2, work package 0, adds the functions of the M1 codecs (time, SPP, EPP; OI-21), and Milestone 5 completes the ABI with the C test harness and the C++ wrapper `aldis.hpp` ([roadmap](../../docs/08-roadmap.md) §1). No header is committed yet; CABI-002 requires the generated header to be committed and CI to fail if it differs from a fresh generation.

## Where it sits

The foreign-function boundary of the [architecture](../../docs/01-architecture.md) §2, above the layers. It depends on the facade `aldis` with the feature `full`, and builds as `staticlib`, `cdylib`, and `rlib`.

## Files

- [`capacities.toml`](capacities.toml): the engine capacities fixed when the library is built, which become `ALDIS_*_MAX_*` constants in the header (CABI-030, GEN-011).
- [`cbindgen.toml`](cbindgen.toml): the header generator's configuration (CABI-002, CABI-003).

## Features

| Feature | Effect |
|---|---|
| `std` (default) | Hosted builds, for ground systems |
| `panic-handler` | A minimal `#[panic_handler]` for `no_std` static-library builds. It only satisfies the linker: no panic path is reachable (GEN-020, VER-010) |

A bare-metal static library is built with:

```sh
cargo build -p aldis-ffi --no-default-features --features panic-handler \
            --target thumbv7em-none-eabihf --release
```

## Guarantees

This is the only library crate in which `unsafe` is allowed. Its lint table sets `unsafe_code` to `deny` instead of the workspace's `forbid`, every `unsafe` block needs a `// SAFETY:` comment (`clippy::undocumented_unsafe_blocks`), and the crate is to be tested under Miri (GEN-071, VER-026). No heap, threads, or C runtime are required on `no_std` targets (CABI-004).

# COP-1 conformance scenarios

Engine scenarios for FOP-1 and FARM-1 (CCSDS 232.1-B-2 and Cor. 1), many scenarios per file, in the format of [07 §3](../../docs/07-test-vectors.md) and `schema/engine-scenario.schema.json`. They are generated by the independent model [`../models/cop1.py`](../models/cop1.py) (TV-023), which was written blind: from the Blue Books and `docs/`, by an agent that had not read any implementation under test; for the layout change only it also read the test infrastructure `crates/aldis-testkit` and the schema generator. `python3 -I test-vectors/models/cop1.py --check test-vectors/cop1/scenarios/*.json` replays every scenario and compares each file with what the generator writes.

The files are in `scenarios/`, below the area directory, so that the exerciser's build script, which reads the files directly in an area directory as codec files, does not read them. File names below are relative to it.

| File | Content | Requirements |
|---|---|---|
| `fop1_table.json` | One scenario per cell of Table 5-1: S1 to S6 by E1 to E46 and E101 to E104 (300 cells) | COP-001, COP-005, TV-011 |
| `farm1_table.json` | One scenario per cell of Table 6-1: S1 to S3 by E1 to E11 (33 cells) | COP-002, COP-005, TV-011 |
| `fop1_ad_service.json`, `fop1_window_timer.json`, `fop1_wrap_directives.json`, `fop1_clcw.json` | FOP-1 behaviour around the cells, by topic: a normal run, retransmission order, Initiate AD with Unlock and Set V(R), BD service, purge; the sliding window, the Wait_Queue, the timer and the limit, suspension; modulo-256 wrap and directive values; CLCW patterns, another VCID, alert suppression | COP-010…COP-017 |
| `farm1_window.json`, `farm1_flow_clcw.json` | FARM-1 behaviour around the cells: window edges, V(R) wrap, retransmission not allowed; FARM-B wrap, buffer flow control, Wait to Lockout, Set V(R) in Lockout, commands that are not commands, the CLCW fields | COP-030…COP-036 |

**The JSON is never edited by hand.** `test-vectors/models/cop1.py --write` writes every file here, in a fixed order and format; `cargo xtask vectors generated` (part of `cargo xtask ci` and the verify check `spec`) regenerates them in a scratch directory and fails on any difference, and `cargo xtask vectors generated --write` (also run by `cargo xtask fix`) rewrites them. Change the model, then regenerate.

Each file gives its provenance and `config` once, and names its **setups**: an input sequence that reaches a state, with its expected outputs, optionally continuing another (`extends`). A scenario refers to a setup by name and lists only its own steps (the trigger). A setup is named after the state it reaches and a hash of its inputs (`S1-3fa9c2d1`), so adding a scenario never renames one; the release check (TV-021) treats the setups of a released file as append-only.

A table-cell scenario is a setup and the trigger. The setup is the shortest input sequence the model found, by breadth-first search over a small alphabet of inputs, that puts the engine in the cell's state with the variables that select the event; the model checks that the trigger reaches exactly the cell its id names. Where a cell shows actions that depend on a "Look for FDU" or "Look for Directive", the setup is one in which the look finds something to send.

## Conventions

* `at_us` is absolute and never decreases; two steps may share an instant. A `timeout` step is placed at the deadline it expires.
* A step lists the complete, ordered outputs of its input (TV-010, TV-012), `expect_state` after it, and the deadline after it: `expect_timeout_us`, or `expect_no_timeout: true` for none (a FOP-1 step always asserts one of them; FARM-1 has no timer). `null` is not a value anywhere in a step.
* An input the engine refuses is `{"error": "<kind>"}` as the only output; the state is unchanged (API-058).
* Handles (`handle`) are chosen by the scenario and are unique in it. A `transmit_done` names the kind of the frame it answers (`AD`, `BC`, `BD`), because at most one request per kind is outstanding (5.1.6); the runner maps the kind to the transmit handle the engine issued.
* Octets are hex strings, keys end in `_hex`. A frame is a complete TC Transfer Frame of `config.frame_target` `"tc"`: header (232.0 4.1.2), data, FECF when `config.fecf` (4.1.4). FOP-1 puts the FDU in the data field as it is (no Segment Header). USLP frames are not covered.

## FOP-1 (`engine: "fop1"`)

`config`: `frame_target`, `scid`, `vcid`, `t1_initial_us`, `transmission_limit`, `timeout_type` (0 or 1), `k`, `fecf`. The engine starts in S6 (Initial) with V(S) = NN(R) = 0, every Out flag Ready, no timer, and Suspend_State 0 (proposed OI: the Blue Book gives no start-up values).

| Input | Fields | Event |
|---|---|---|
| `clcw` | `lockout`, `wait`, `retransmit`, `n_r`; optional `cop_in_effect` (default 1), `control_word_type` (default 0), `vcid` (default the channel's) | E1…E15, E101…E103; another `vcid` is refused with `UnknownChannel` and changes nothing |
| `timeout` | none; fed at `at_us` | E16…E18, E104 when the timer is armed and `at_us` has reached it; otherwise it changes nothing and gives no output (API-053) |
| `request_ad`, `request_bd` | `handle`, `data_hex` | E19, E20; E21, E22 |
| `directive` | `handle`, `type`, and `value` where it has a qualifier: `initiate_ad_without_clcw_check`, `initiate_ad_with_clcw_check`, `initiate_ad_with_unlock`, `initiate_ad_with_set_vr` (`value` V*(R)), `terminate_ad`, `resume_ad`, `set_v_s` (V*(S)), `set_k`, `set_t1_initial` (microseconds), `set_transmission_limit`, `set_timeout_type` | E23…E40; a value outside its range (K 1..255, V(S) and V(R) 0..255, limit 1..255, T1 at least 1, type 0 or 1) or an unknown type is E40 |
| `transmit_done` | `kind`, `response` (`accept` or `reject`) | E41…E46 |
| `table_event` | `event`, and for E19 to E22 an `input` that gives the payload | Conformance only: the event number is fed to the table without classification, in the engine's current state. For a cell marked Not applicable the output is `{"error": "InvalidState"}`; the other injected cells run their actions |

Outputs, in the order of the cell (COP-006):

| Output | Meaning |
|---|---|
| `{"transmit": {"kind", "ns", "retransmission", "frame_hex"}}` | Transmit Request for Frame (AD with N(S) = V(S); BC with N(S) 0 and Unlock `00` or Set V(R) `82 00 vv`; BD with N(S) 0) |
| `{"event": "abort"}` | Abort Request to the Lower Procedures, first action of Initiate AD (or BC) Retransmission (5.2.7 a) |
| `{"event": "transfer_notify", "handle", "type"}` | `accept`, `reject`, `positive_confirm`, `negative_confirm` (4.4) |
| `{"event": "directive_notify", "handle", "type"}` | the same four for a directive (4.2) |
| `{"event": "alert", "reason", "event_number", "prior_state"}` | `limit`, `t1`, `lockout`, `synch`, `nn_r`, `clcw`, `llif`, `term` (Table 4-4); after the purges of 5.2.15 |
| `{"event": "suspend"}` | the Suspend notification (4.3.3) |

## FARM-1 (`engine: "farm1"`)

`config`: `frame_target`, `scid`, `vcid`, `fecf`, `status_field`, `window` (`{"retransmission_allowed": true, "w": W}` with PW = NW = W/2, or `{"retransmission_allowed": false, "w": W, "pw": PW}` with NW = W - PW; Cor. 1 6.1.8.3), `v_r`. It starts in S1 with the three flags and the FARM-B Counter at 0 (OI-58).

| Input | Fields | Event |
|---|---|---|
| `frame` | `frame_hex` (a TC frame that passed the Frame Validation Checks), `buffer_available` | E1…E9; a Type-AD frame with N(S) = V(R) is E1 with `buffer_available` and E2 without; a Type-BC frame with neither Unlock nor Set V(R) is E9 |
| `invalid_frame` | none | E9 |
| `buffer_released` | none | E10 |
| `query` | `"clcw"` | E11; output `{"clcw": {...}, "clcw_hex": "..."}` (232.0 4.2.1) |
| `set_physical_flags` | `no_rf_available`, `no_bit_lock` | none (not part of COP) |

Outputs: `{"deliver": {"kind", "ns", "data_hex"}}` (Accept; `ns` 0 for BD), `{"event": "frame_discarded", "event_number", "state"}` (Discard; `state` is the state before), `{"event": "unlocked"}` (an Unlock command was executed), `{"event": "state_changed", "event_number", "from", "to"}` (last, only when the state changes). FARM-1 has no timer.

## Cells that no ordinary input reaches

Coverage is every cell of both tables. These cells are driven differently from the rest. The reasons are the Blue Book's variables, except for the S4/S5 group, which also depends on OI-60 (a purge sets NN(R) := V(S); the Blue Book is silent on it, and without it a purge in S6 leaves NN(R) different from V(S) and an ordinary CLCW can then select those events in S4 and S5):

* **FOP-1, "Not applicable" (48 cells).** `{"table_event": {"event": n}}`, expecting `InvalidState` and no state change (COP-005). The conditions of these events cannot hold in these states: E2, E5 to E12, E101 to E103 in S4 and S5 (given OI-60, S4 and S5 hold no AD frame, so NN(R) = V(S) and the only valid N(R) is that value); E16, E104, E17, E18 in S6 (no timer runs in Initial); E31 to E34 in S1 to S5 (Suspend_State is non-zero only in S6). `--audit` of the model searches for an input that classifies into one of them and finds none. It is a bounded search, not a proof: depth 9, 4091 nodes, an alphabet of 43 inputs for FOP-1.
* **FARM-1 (S2, E1).** Reached by an ordinary input: a Type-AD frame with N(S) = V(R) and `buffer_available` true while in Wait. The engine refuses it with `InvalidState` (cop1.md 3.2, COP-005).
* **FOP-1, applicable but unreachable (4 cells).** `table_event` after a setup, expecting the actions of the cell: (S2, E1) and (S3, E1), because E1 needs N(R) = V(S) = NN(R), an empty Sent_Queue, which S2 and S3 never have; (S4, E20) and (S5, E20), because E20 needs an occupied Wait_Queue, which Initialize empties and S4 and S5 never fill.

## Readings the model makes

The maintainer accepted these on 2026-10-30 (chat). The start-up values, the effect of a purge on NN(R), and the two Accepts are OI-59, OI-60, and OI-61; the rest are written into [cop1.md](../../docs/standards/cop1.md).

1. Start-up values of FOP-1 (above): OI-59.
2. A purge of the Sent_Queue sets NN(R) := V(S): OI-60. The model applies it in `purge_sent`. The S4/S5 Not applicable group depends on it (above).
3. E21 and E45 both list "Accept"; both are kept as printed: OI-61. The question to CCSDS whether the E45 Accept is a Rev. B leftover stays open, and the E45 scenarios of `fop1_table.json` and `bd-service` in `fop1_ad_service.json` change with its answer.
4. The Abort Request of "Initiate AD (or BC) Retransmission" (5.2.7 a) is an output, `abort`, and does not change the Out flags; it counts in FOP-1's `N` (COP-006).
5. A Type-BC frame in the Sent_Queue is purged without a notification of its own; an Initiate AD directive that awaits its confirmation gets its negative confirmation from Alert (5.2.15 d).
6. Event precedence (OI-62, open): the model classifies an invalid bit pattern (E15) first, then Lockout (E14), then N(R) (E13). §5.3.2.1 settles only the order Lockout, N(R), Retransmit, Wait. No vector combines these conditions, so none depends on the order.
7. FARM-1 emits `state_changed` when, and only when, the state changes, after the actions of the cell, and `unlocked` for every Unlock (COP-036).
8. The Lockout and Wait Flags are functions of the state, not stored: Lockout is set exactly in S3 and Wait exactly in S2 (232.1-B-2 6.1.3, 6.1.4; OI-64). The model's FARM-1 derives both from the state and does not apply the flag actions of Table 6-1, which it keeps as printed; `check_farm_flag_actions` verifies that each cell's actions agree with its next state, with (S2, E5) as the one exception (it enters S3 and lists no clearing of the Wait Flag). After S2, E5 the CLCW shows Wait 0 and Lockout 1: scenario `cop1-farm1-wait-to-lockout`. No other vector observes the difference.
9. `table_event` stays a conformance-only input. The schema's deadline is `expect_timeout_us` or `expect_no_timeout`, and one file holds many scenarios with named setups (`ScenarioFile::resolve` in `aldis-testkit` expands them). The runner pull request adds the engine input and removes `"cop1/scenarios/"` from `AWAITING_RUNNER` in `xtask/src/consistency.rs` (the exemption from the "a test runs it" check). Files under the exemption are also no evidence for `cargo xtask trace` (`trace.rs` skips them).
